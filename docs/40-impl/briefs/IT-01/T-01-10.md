### 4.6 T1 생성기 (`domain/itembank/t1/**` 순수 + `application/itembank/t1/**`, PGM-CT-082)

```ts
export type T1ParamSpec = { readonly type: 'int'; readonly min: number; readonly max: number; readonly step: number }
                        | { readonly type: 'enum'; readonly values: Readonly<Record<string, string>> };
export type T1Instance = {
  readonly generator: 't1.event_loop_order' | 't1.http_status';
  readonly params: Readonly<Record<string, number | string>>;   // 샘플링된 값
  readonly code: string; readonly stem_md: string;
  readonly expected_stdout: string;                             // 줄 = '\n' 연결, 끝 '\n' 없음(T-01-05 §4.6 규약)
};
export interface T1Generator {
  readonly id: T1Instance['generator'];
  readonly defaultParams: Readonly<Record<string, T1ParamSpec>>;
  generate(params: Readonly<Record<string, T1ParamSpec>>, rng: () => number): T1Instance;   // rng ∈ [0,1)
}
export const T1_GENERATORS: Readonly<Record<T1Instance['generator'], T1Generator>>;
```
- **샘플링(`params.ts`)**: 키를 사전순으로 돌며 int = `min + step × floor(rng() × (floor((max − min)/step) + 1))` · enum = 값 키 사전순 배열의 `floor(rng() × n)`. `step` 기본 1.
- **`application/itembank/t1/seeded-rng.ts`**: `seededRng(seed: number): () => number` = mulberry32(`seed >>> 0`) [Brief 결정]. `generate.ts`: `generateT1(generator, params, seed): T1Instance`(같은 시드 → 같은 인스턴스, FR-QST-001). `parse-slots.ts`: `ib_item_model.slots_json`(`{generator, params}`, T-01-03 §4.8) → zod(로컬 `T1Slots`, DCP §6.6 `ParamSpec` 모양, `step` 기본 1) → `Result<{generator, params}, {kind:'invalid_slots'|'unknown_generator'}>`. 지원 생성기 밖 = `unknown_generator`.
- **`event_loop_order`**(params 키 = T-01-05 §4.4: `n_sync` 1..3 · `n_microtask` 1..3 · `n_macrotask` 1..2 · `nesting` {none, micro_in_macro, macro_in_micro} · `apis` {basic, with_queue_microtask, with_await}; `defaultParams` = 이 값 그대로):
  1. 최상위 문장 목록 = `console.log('S<i>')` × n_sync + 마이크로 등록 × n_microtask(`Promise.resolve().then(() => { console.log('M<i>'); })`; `with_queue_microtask`면 **첫 번째는 반드시** `queueMicrotask(() => { … })`, 나머지는 rng로 둘 중 선택) + `setTimeout(() => { console.log('T<i>'); }, 0)` × n_macrotask. 목록을 rng Fisher–Yates로 섞는다.
  2. `with_await`: 맨 위에 `async function f() { console.log('A1'); await null; console.log('A2'); }` 선언, 섞인 목록의 rng 위치에 `f();` 삽입(A1 = 그 자리 동기 출력, A2 = 그 시점에 큐에 들어가는 마이크로태스크).
  3. `micro_in_macro`: **첫 번째로 등록된** setTimeout 콜백 안, 로그 뒤에 `Promise.resolve().then(() => { console.log('N1'); });` · `macro_in_micro`: 첫 번째로 등록된 마이크로태스크 콜백 안, 로그 뒤에 `setTimeout(() => { console.log('N1'); }, 0);`.
  4. **기대 출력 = 순수 모형**: 최상위 실행(동기 로그·큐 적재) → 마이크로 큐 FIFO 완전 소진(소진 중 추가분 포함) → 매크로 큐 FIFO에서 하나 실행 → 마이크로 소진 → 반복. `setTimeout(…, 0)`은 모두 같은 지연이므로 등록 순서 = 실행 순서(나중 등록 N1은 앞선 T 뒤). `process.nextTick`·`setImmediate`·`.then` 체인·0이 아닌 지연은 **생성하지 않는다**(T-01-05 §4.4).
  5. `code` = 위 문장들(2칸 들여쓰기, 줄마다 `;`), `stem_md` = `다음 코드를 Node.js로 실행했을 때 출력되는 내용을 순서대로 쓰시오.`
- **`http_status`** [Brief 결정 — 네트워크 0, 순수 핸들러 실행 결과 예측. 콘텐츠 item-model이 아직 없으므로 `defaultParams`가 정본]: `defaultParams = { n_requests: {int 1..3}, order: {enum {auth_first: "인증 검사 먼저", exists_first: "존재 검사 먼저"}} }`. 코드 = 고정 `store`(`a1`: version 3, `b2`: version 1) + `handle(req)` 규칙 목록(`auth_first`: ① `token === null` → 401 ② `DELETE ∧ role !== 'admin'` → 403 ③ `method !== 'POST' ∧ !store.has(id)` → 404 ④ `PUT ∧ version !== store.get(id).version` → 409 ⑤ POST → 201 ⑥ DELETE → 204 ⑦ 200; `exists_first`: ③을 ①보다 앞에) + 요청마다 `console.log(handle({ method, id, token, role, version }));` — 요청 필드는 rng로 `method ∈ {GET,POST,PUT,DELETE}` · `id ∈ {a1,b2,zz}` · `token ∈ {'t0', null}` · `role ∈ {admin,user}` · `version ∈ {1,3}`. 기대 출력 = 같은 규칙의 TS 모형 평가. `stem_md` = `다음 코드를 실행했을 때 출력되는 HTTP 상태 코드를 순서대로 쓰시오.`
- 생성 결과를 문항 레코드로 굳히는 일(`ib_item` 런타임 행·gate)은 하지 않는다(IT-01 출제 경로 = 시드 문항) [Brief 결정]. `toCodePredictParts(i: T1Instance)` = `{ stem: { md: stem_md, code: { lang: 'js', src: code } }, options: {}, answer_key: { stdout: expected_stdout } }`(T-01-03 §4.8 code_predict 행과 같은 모양)만 제공.

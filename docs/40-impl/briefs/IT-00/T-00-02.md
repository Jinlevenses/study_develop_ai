## 4. 동작 규약

### 4.1 전사 규칙 (전 파일 공통)

1. 코드 블록의 `export const`·주석·정규식·숫자·필드 순서를 **그대로** 옮긴다. 이름 변경·필드 추가·`.optional()` 추가·정규식 "개선" 금지. 블록 안 주석은 남겨도 되고(권장) 지워도 된다.
2. 블록마다 각 `export const X = <zod schema>` 바로 아래에 `export type X = z.infer<typeof X>;`를 둔다(값과 타입 같은 이름 — TS가 허용). 함수·제네릭 헬퍼(`S`·`Page`·`defineRoute`)·`interface`·`type`은 그대로.
3. 블록이 다른 파일의 이름을 쓰면(예: `admin-routes.ts`의 `EventType`) **그 이름을 정의한 파일을 상대 import**한다. 정의 위치: `S`=`common/schema` · ID 스칼라=`common/ids` · 시간=`common/time` · 도메인 스칼라=`common/domain` · `AttemptPhase`·`PromotionGate`·`WGraderTable`=`common/practice` · `EventType`·`IntegrationEventEnvelope`=`events/envelope` · `ModuleSchemaVersions`·`LedgerHead`=`admin/admin-routes`.
4. `z`는 `import { z } from 'zod'`. 타입 위치에서만 쓰면 `import type`(verbatimModuleSyntax — `tsc`가 알려 준다).
5. 코드 블록이 **컴파일되지 않거나 서로 모순**되면(이름 미정의 등) 고쳐 쓰지 말고 §7 `contract_change`로 멈춘다. 단, 아래 §4.4의 [Brief 결정] 3건은 이미 판정된 것이므로 그대로 적용한다.
6. **zod 4 의미 주의(바꾸지 말 것)**: `z.record(<z.enum 또는 ServiceName>, V)`는 zod 4에서 **전 키 필수(exhaustive)**다(예: `SnapshotResult.delivery`, `BootstrapEnvelope.callers`·`peers`, `AdminEventsView.delivered`, `MasteryRulesV1.assessment.accuracy_min_correct`·`ai_profiles`). 원문 그대로 두고, 이 의미를 테스트로 **고정 단언**한다(UT-CON-047). **[Brief 결정]** 해석: 서비스는 비목적지·해당 없음 키에 `0`/`false`를 채운다. (`LedgerHead`처럼 키가 정규식 문자열이면 비전수 — 그대로.)

#### 4.1.3 잠금 (`runtime-files.ts`의 `acquireLock`)
- `fs.open(lockPath, 'wx', 0o600)` → `SupervisorLockFile` JSON 1줄 쓰기 → `fsync` → close.
- `EEXIST` → 읽어 파싱: 파싱 실패이거나 `pid`가 죽음(`process.kill(pid, 0)`이 `ESRCH`) → **stale**: `writeFileAtomic`로 덮어쓰고 `{acquired: true, previousCrashed: true}` · pid 생존(성공 또는 `EPERM`)이며 자기 pid가 아님 → `{acquired: false}`(main이 75로 종료).
- `previousCrashed = true`면 이번 boot의 **모든 첫 fork** 봉투에 `flags.after_crash = true`(직전 supervisor가 비정상 종료 — SP-4 감사 "크래시 후 무결성").
- 정상 종료(§4.1.10 끝) 시 `supervisor.lock`·`cli.token` 삭제, `registry.json`은 `state: 'stopped'`로 남긴다.

#### 4.1.4 자식 생성 (`child.ts`, `child-env.ts`, `bundle.ts`)
```ts
export type ChildSpec = { readonly svc: SupervisedService; readonly kind: 'fork' | 'spawn'; readonly entry: string; readonly args: readonly string[];
  readonly execArgv: readonly string[]; readonly env: Readonly<Record<string, string>>; readonly cwd: string };
export interface ChildHandle { readonly pid: number | null; send(msg: unknown): boolean; treeKill(): void;
  onMessage(cb: (m: unknown) => void): void; onExit(cb: (code: number | null, signal: string | null) => void): void;
  onLine(cb: (stream: 'stdout' | 'stderr', line: string) => void): void }
export type SpawnChild = (spec: ChildSpec) => ChildHandle;
export function realSpawnChild(deps?: { platform?: NodeJS.Platform }): SpawnChild;
```
- `fork`(서비스 5종): `fork(entry, args, { execArgv, env, cwd, stdio: ['ignore','pipe','pipe','ipc'], serialization: 'json', detached: platform !== 'win32', windowsHide: true })`. `spawn`(vite): `spawn(process.execPath, [...execArgv, entry, ...args], { env, cwd, stdio: ['ignore','pipe','pipe'], detached: platform !== 'win32', windowsHide: true, shell: false })`. **[Brief 결정]** `detached`(POSIX) = 자식이 프로세스 그룹 리더가 되어 `treeKill`(`kill(-pid)`)이 손자(job)까지 닿는다. supervisor 사망 시 정리는 그룹이 아니라 **IPC 끊김**으로 한다(ADR-012 §4).
- stdout·stderr는 `setEncoding('utf8')` + 줄 분리(마지막 미완 줄 버퍼, 줄당 8,000자 초과분 절단) → `onLine`. `treeKill()` = `@fathom/shared-kernel/proc/proc`의 `treeKill(pid)`.
- 서비스 args = `['--mode=serve', ...testArgs]`(T-00-08은 `--mode` 생략 = serve지만 명시한다). `cwd` = app root(`--import tsx` 해석 기준).
- **진입 파일**(`bundle.ts` `resolveEntries(appRoot, runtime, profile)`, 경로는 `fileURLToPath(new URL(<상수 상대 경로>, appRootUrl))` — 문자열 연결 0, STD-TS-42): 디렉터리 `{gateway:'gateway', content:'content', learning:'learning', 'ai-gateway':'ai-gateway', 'ops-api':'ops'}` · `src` → `services/<dir>/src/main.ts`, execArgv `['--disable-warning=ExperimentalWarning','--import','tsx','--conditions=source']` · `dist` → `services/<dir>/dist/main.js`, execArgv `['--disable-warning=ExperimentalWarning']` · `vite`(profile `dev`만) → entry `apps/web/node_modules/vite/bin/vite.js`, args `['--host','127.0.0.1','--port','5173','--strictPort']`, cwd `apps/web`, execArgv `['--disable-warning=ExperimentalWarning']`.
- **`--entries` JSON(test 전용)** = `{ "<SupervisedService>": { "entry": "<abs>", "execArgv": [..], "args": [..] } }`(부분 지정 가능, zod strict, 경로는 절대) → 해당 서비스의 진입·execArgv를 대체하고 `args`를 `--mode=serve` 뒤에 붙인다.
- **자식 env**(`childEnv(home, deps)`, ADR-012 §2, STD-CFG-21): 새 객체에 `PATH`·`HOME`·`LANG`·`LC_ALL`·`TMPDIR`·`TZ`(+ win32 `SYSTEMROOT`·`APPDATA`·`LOCALAPPDATA`·`USERPROFILE`) 중 `readAllowedEnv`로 값이 있는 것만 + `FATHOM_HOME = home` + `NODE_OPTIONS = mergeNodeOptions(readAllowedEnv('NODE_OPTIONS'))`. API 키·`CI`·프록시·그 밖 변수 0(**[Brief 결정]** ADR-012 §2 "토큰·키 없음"이 STD §8.3의 env 키 3순위보다 우선 — CR 후보 ⑤).
- `mergeNodeOptions(existing: string | undefined): string` — 공백 분리 토큰에 `--disable-warning=ExperimentalWarning`이 이미 있으면 원문 그대로(트림), 없으면 `[existing, FLAG].filter(Boolean).join(' ')`(기존 값 보존, UT-SUP-005).

#### 4.1.5 재시작 정책 (`restart-policy.ts`, 순수) — ADR-012 §7, ARC §14.2 표

```ts
export function decideOnExit(i: ExitInput): { readonly decision: ExitDecision; readonly crashTimes: readonly number[] };
export const RESTART_DELAYS_MS = [250, 1000, 2000] as const;  // ADR-012 §7
export const CRASH_WINDOW_MS = 60_000; export const MAX_CRASHES_IN_WINDOW = 3;  // NFR-AVL-003
```
- `requested`(supervisor가 보낸 shutdown·stop·dev 재기동·run_mode 선행 정지) → `stopped`(`reason: 'requested'`), 크래시 이력 불변.
- `code === 0` → `stopped`(`'exit_0'`). `code === 78` → `degraded`(`'exit_78:' + (fatalCode ?? 'unknown')`) — 재시작 안 함.
- 그 밖(64·70·75·기타·`code === null` 신호 사망·ready 시간 초과) = 크래시: `window = crashTimes.filter(t => now − t < 60_000)` + `now`. `window.length > 3` → `degraded`(`'crash_loop'`). 아니면 `delayMs = code === 75 ? 0 : RESTART_DELAYS_MS[window.length − 1]`(**[Brief 결정]** 75 = 즉시 재시작, 창 계수는 같이 함).
- `svc.start`(운영자 재시작)·dev 재기동은 크래시 이력을 비운다.

- `output.ts`(STD-LOG-40): `createOutput({stdout, stderr, json})` → `info(text)`·`warn(text)`·`result(obj)`(`--json`이면 명령 끝에 JSON 1개만 stdout, 사람용 문장 0)·`error({code, title, error_id?})`(stderr: `오류 [<code>] <title>` + error_id 있으면 `(error_id: …)`). 쓰기는 `stream.write`(console 0). **토큰·`#bt=`가 포함된 문자열은 출력 금지** — `result`/`info`에 `#bt=`가 있으면 `invariant` 던짐(방어).

#### 4.2.7 명령 (`src/commands/*.ts`)
- **`up`**: Node 버전 → home → `ensureRunning`(foreground면 spawn은 attached) → 성공 시 `--no-open`이 아니면 `POST /api/v1/cli/bootstrap-token` `{purpose: 'up'}` → 201 + `pickOpenUrl` → `openBrowser(url)` → 출력 `Fathom 실행 중: http://127.0.0.1:<port>/`(fragment 없이) + 안내·degraded 경고 → 전원 ready면 0, degraded 서비스가 있으면 7. **foreground**: 성공 출력 후 supervisor `exited`를 기다려 그 코드가 0이면 0 아니면 1. CLI 자신의 `SIGINT`·`SIGTERM`은 무시(같은 프로세스 그룹의 supervisor가 받아 정상 종료 — `run.ts`가 아니라 `main.ts`에서 no-op 핸들러 설치, foreground 모드에서만).
- **`open`**(FR-SET-023, UC-36 "꺼져 있으면 기동"): `up`과 같은 `ensureRunning`(prod 기본, foreground 아님) → `{purpose: 'open'}` → `openBrowser`(`--no-open`이면 생략) → 0/7. 브라우저 열기 실패 → `FAILED`(1) + "브라우저를 열지 못했습니다 — 다시 `fathom open`"(URL·토큰 출력 0).
- **`status`**: 잠금 없음/죽음 → `CLI-DEP-001`/3("꺼져 있음") · `GET /api/v1/cli/status` 200 → 표시 + 0 · `connect`/`timeout`/비 2xx → `readRegistry`로 서비스 표(이름·state·port·restarts) 표시 + **7**(부분) · Problem → `exitForProblemCode`.
- **`down`**: 잠금 없음/죽음 → "실행 중이 아님" + **0**(멱등) · `POST /api/v1/cli/shutdown` `{op_id: <idempotency-key와 같은 ULID>, grace_ms: 3000}` → 202면 대기로 · 그 밖(연결 실패·토큰 없음·4xx/5xx) → **폴백 신호**: POSIX `process.kill(lock.pid, 'SIGTERM')` / win32 `safeSpawn('<SYSTEMROOT>\\System32\\taskkill.exe', ['/PID', String(pid)], …)`(`/T /F` 없음 — 자식은 IPC 끊김으로 정상 종료) → **대기**: 100ms 폴링, 15,000ms 안에 pid 사망 → 0, 아니면 `FAILED`(1) "종료하지 못했습니다".

#### 4.2.8 브라우저 열기 (`lib/browser-open.ts`) — IF-EXT-15
- `openBrowser(url, deps)`: darwin `safeSpawn('/usr/bin/open', [url])` · linux `PATH`(`readAllowedEnv('PATH')`)의 디렉터리를 순서대로 보며 실행 가능한 `xdg-open` 절대 경로 → `safeSpawn(<abs>, [url])`(없으면 실패) · win32 `safeSpawn('<SYSTEMROOT>\\System32\\rundll32.exe', ['url.dll,FileProtocolHandler', url])`. `cmd /c start`·셸 0. `safeSpawn` 옵션: `env` = §4.2.5 allowlist(NODE_OPTIONS 제외), `cwd` = home, `timeoutMs: 10_000`. exit ≠ 0·`spawnError`·`timedOut` → 실패.
- **알려진 제약 [Brief 결정 — CR 후보 ②]**: Linux 데스크톱의 `xdg-open`은 `DISPLAY`·`WAYLAND_DISPLAY`·`XDG_RUNTIME_DIR`·`DBUS_SESSION_BUS_ADDRESS`가 필요하지만 STD §8.3 허용 표에 없어 넘길 수 없다. 이 Task는 표를 넓히지 않는다(실패 시 위 안내). E2E는 Playwright가 bootstrap-token을 직접 쓰므로 IT-00 판정에 영향 없음.

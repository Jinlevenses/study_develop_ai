### 4.1 WP-00-20 — `sqlite/`

#### 4.1.1 `openDb` · `SqlitePort` (`sqlite/sqlite.ts`)
```ts
export type BindValue = number | string | bigint | Uint8Array | null;
export type BindArgs = readonly BindValue[] | readonly [Readonly<Record<string, BindValue>>];
export interface Stmt {
  run(...args: BindArgs): { changes: number; lastInsertRowid: number | bigint };
  get(...args: BindArgs): Record<string, unknown> | undefined;
  all(...args: BindArgs): Record<string, unknown>[];
  iterate(...args: BindArgs): IterableIterator<Record<string, unknown>>;
}
export interface SqlitePort {
  readonly path: string; readonly readOnly: boolean;
  prepare(sql: string): Stmt; exec(sql: string): void; tx<T>(fn: () => T): T;
  fn(name: string, impl: (...args: BindValue[]) => BindValue, opts?: { deterministic?: boolean }): void;
  close(): void;
}
export type OpenDbOptions = { readonly readOnly?: boolean; readonly synchronous: 'NORMAL' | 'FULL'; readonly recursiveTriggers?: boolean; readonly metrics?: MetricsRegistry };
export function openDb(path: string, opts: OpenDbOptions): SqlitePort;
```
- `opts`의 키가 `readOnly`·`synchronous`·`recursiveTriggers`·`metrics` 밖이면 던짐(UT-SK-001). **[Brief 결정]** `metrics`는 ARC 시그니처에 가산한 선택 키.
- 생성자 = `new DatabaseSync(path, { readOnly, timeout: 5000, enableForeignKeyConstraints: true, enableDoubleQuotedStringLiterals: false })`(고정, `allowExtension` 미지정). `node:sqlite`는 정적 import(경고 억제는 진입점 = T-00-08 몫).
- 연결 직후 PRAGMA(정적 상수만, 템플릿 금지): `PRAGMA synchronous=NORMAL` 또는 `=FULL`(두 상수 중 선택) · `recursiveTriggers`면 `PRAGMA recursive_triggers=ON` · 쓰기 연결이면 `PRAGMA journal_size_limit=67108864`. WAL·`application_id`는 여기서 설정하지 않는다(migrate 몫).
- 바인딩 가드(UT-SK-003): 위치 인자·명명 객체 값 모두 `BindValue` 외(`Date`·`boolean`·`undefined`·객체·함수)면 `Error('invariant: sqlite bind <type> at <index|name>')`. 가드는 `Stmt` 래퍼에서 실행 전 검사.
- `tx(fn)`(UT-SK-002, SP-4 이식): 이미 `isTransaction`이면 던짐(중첩 금지) → `exec('BEGIN IMMEDIATE')` → `fn()` → 반환값이 thenable이면 ROLLBACK 후 `Error('invariant: tx fn returned a Promise')` → `COMMIT`. 예외 시: `classifySqliteError`로 분류해 메트릭 증가 → `isTransaction`이면 ROLLBACK → **원 오류를 다시 던짐**(ROLLBACK도 실패하면 `new Error('invariant: rollback failed', { cause: new AggregateError([orig, rbErr]) })`). 재시도 0(517 포함).
- 메트릭(있을 때만, 라벨 `db` = 파일 basename, `:memory:` → `memory`): `sqlite_busy_total{db}`·`sqlite_busy_snapshot_total{db}` 카운터, `sqlite_tx_duration_ms{db}` 히스토그램(버킷 `[1,5,10,25,50,100,250,1000]`, `performance.now()` 차이).
- `close()` 두 번째 호출은 무시(이미 닫힘) — `isOpen` 검사.

#### 4.1.2 SQL 조각 · 오류 분류
- `ident(name)`: `/^[A-Za-z_][A-Za-z0-9_]*$/` 통과 시 `"name"`, 아니면 던짐 · `placeholders(n)`: 정수 1~999 → `'?, ?, …'`(`', '` 구분), 아니면 던짐 · `sqlInt(n)`: `Number.isSafeInteger` → `String(n)`, 아니면 던짐.
- `classifySqliteError(e: unknown): { kind: 'busy'|'locked'|'constraint'|'readonly'|'busy_snapshot'|'other'; errcode: number | null }` — `errcode === 517` → `busy_snapshot`(먼저 검사), 그다음 `errcode & 0xff`: 5 busy · 6 locked · 19 constraint · 8 readonly · 그 외 other. `errcode`가 없으면 `{other, null}`(UT-SK-004).

#### 4.1.3 `vacuumInto` (job 전용)
```ts
export function vacuumInto(db: SqlitePort, destPath: string): Promise<Result<{ path: string; bytes: number; sha256: string }, { reason: 'exists' | 'integrity_failed' | 'io'; detail: string }>>;
```
목적 파일 존재 → `exists` · `tmp = <dest>.<ulid()>.tmp` · `db.prepare('VACUUM INTO ?').run(tmp)` · tmp를 `openDb(tmp,{readOnly:true, synchronous:'NORMAL'})`로 열어 `PRAGMA integrity_check` 결과가 정확히 1행 `ok`가 아니면 tmp 삭제 후 `integrity_failed` · close → `rename(tmp, dest)` · 크기·sha256(스트리밍 `pipeline`)을 돌려줌. `DatabaseSync.backup()` 사용 금지.

#### 4.1.4 마이그레이션 실행기 (`sqlite/migrate.ts`, 진입 파일이 재공개)
```ts
export type MigrationDir = { readonly module: string; readonly dir: string };            // 배열 순서 = 적용 순서(`_infra` 먼저)
export type MigrationFile = { readonly module: string; readonly version: number; readonly name: string; readonly file: string; readonly sha256: string;
  readonly kind: 'additive' | 'destructive'; readonly adr: string | null; readonly fkOff: boolean; readonly profiles: readonly ('meta' | 'full')[] | null; readonly sql: string };
export type MigrateFailure = { readonly reason: 'header_invalid' | 'name_invalid' | 'gap' | 'forbidden_token' | 'application_id_mismatch' | 'sha_mismatch'
  | 'downgrade' | 'needs_migrate' | 'apply_failed' | 'integrity_failed'; readonly exitCode: 1 | 78; readonly file: string | null; readonly detail: string };
export type MigrateOptions = { readonly dryRun: boolean; readonly profile: 'meta' | 'full'; readonly applicationId: number; readonly clock: Clock };
export type MigrateReport = { readonly dryRun: boolean; readonly applied: readonly { module: string; version: number; name: string; sha256: string }[];
  readonly pending: readonly { module: string; version: number; name: string }[]; readonly schemaVersions: Readonly<Record<string, number>> };
export function readMigrationBundle(dirs: readonly MigrationDir[]): Result<MigrationFile[], MigrateFailure>;

export function verifySchema(db: SqlitePort, dirs: readonly MigrationDir[], opts: { readonly profile: 'meta' | 'full' }): Result<{ schemaVersions: Readonly<Record<string, number>> }, MigrateFailure>;
```
- **번들 읽기**(기동 시 1회 — 동기 fs 허용): 디렉터리의 `*.sql`만, 파일명 `^(\d{4})_([a-z0-9_]+)\.sql$` 아니면 `name_invalid` · 번호가 0001부터 연속이 아니면 `gap` · 1행 헤더 정규식 `^-- @fathom:module=([a-z_][a-z0-9_-]*) version=(\d+) kind=(additive|destructive)( adr=ADR-\d{3})?( fk=off)?( profile=(meta|full)(,(meta|full))*)?$`, module = 디렉터리의 module, version = 파일 번호, **[Brief 결정]** `destructive`면 `adr=` 필수 — 위반 `header_invalid` · sha256 = 파일 **바이트** 해시. 위 실패의 `exitCode` = 78.
- **금지 토큰 렉서 [Brief 결정 — DDL의 `CREATE TRIGGER … BEGIN … END;`와 충돌 해소]**: `--` 줄 주석·`/* */`·`'…'` 문자열·`"…"` 인용 식별자를 걷어낸 토큰열에서 ① 최상위 **문장의 첫 키워드**가 `BEGIN`·`COMMIT`·`END`·`ROLLBACK`·`SAVEPOINT`·`RELEASE`·`PRAGMA`·`ATTACH`·`DETACH`·`VACUUM`이면 위반 ② 어디서든 단독 토큰 `PRAGMA`·`ATTACH`·`DETACH`·`VACUUM`·`load_extension`이면 위반(대소문자 무시, 단어 경계 — `pragma_table_info` 같은 식별자는 단독 토큰이 아님). 최상위 문장 분할: `;`로 나누되, `CREATE [TEMP|TEMPORARY] TRIGGER`로 시작한 문장은 그 안의 `BEGIN`·`CASE`가 깊이 +1, `END`가 −1이며 깊이 0에서 만난 `;`까지가 한 문장. 위반 = `forbidden_token`(78, `detail`에 토큰·줄 번호).
- **migrate 흐름**(DB-01 §11.2): `PRAGMA application_id` 읽기 → 0이면(dryRun 아님) `PRAGMA application_id = ${sqlInt(id)}` + `PRAGMA journal_mode=WAL` / 기대값이면 `PRAGMA journal_mode=WAL` / 그 외 `application_id_mismatch`(78) → `schema_migrations`가 있으면 `(module, version, sha256)` 전부 읽기(없으면 빈 집합) → 번들과 대조: DB에만 있는 행 `downgrade`(78) · 같은 키 다른 sha `sha_mismatch`(78) · DB 행이 모듈 안에서 1부터 연속이 아님 `gap`(78) → 미적용 파일 중 헤더 `profile`이 있고 `opts.profile`을 포함하지 않으면 건너뜀(없으면 적용) → `dryRun`이면 여기서 `pending` 목록으로 반환(DB 무변경 — **[Brief 결정]** 사본 실행형 dry-run은 서비스 `--mode=migrate --dry-run`이 사본 DB에 `dryRun:false`로 호출) → 파일마다 `tx(() => { exec(file.sql) /* sql-ok: sha256 검증된 번들 파일 */; INSERT INTO schema_migrations(module, version, name, sha256, applied_at) VALUES (?, ?, ?, ?, ?) })`, `fkOff`면 tx 밖 `PRAGMA foreign_keys=OFF` → tx 안 본문 후 `PRAGMA foreign_key_check` 0행 단언(아니면 던져 ROLLBACK) → tx 밖 `PRAGMA foreign_keys=ON`. 실패 = `apply_failed`(exitCode **1**, 앞서 커밋된 파일은 남음) → 끝에 `PRAGMA integrity_check` = `ok`(아니면 `integrity_failed`, 1) + `PRAGMA optimize` → `schemaVersions = {module: max(version)}`.
- **verifySchema**(serve 모드, DB-01 §11.3): profile 필터를 적용한 번들 집합과 DB 행 집합 비교 — 같음 ok · DB가 뒤처짐 `needs_migrate` · DB에 모르는 행 `downgrade` · sha 다름 `sha_mismatch`(전부 78).
- `migrate`·`verifySchema`·`openDb`의 PRAGMA 실행은 shared-kernel 안 이 두 곳에서만(STD-SQL-04).

- 헤더 형식 `^Bearer ([0-9a-f]{64})$`(없음 `missing`, 형식 오류 `malformed`). 토큰을 hex 디코드한 32바이트와 **등록된 모든 항목을 끝까지** `crypto.timingSafeEqual`로 비교(일치해도 조기 종료 0), 일치 1개 → 그 서비스. `checkInternalAccess`: identify 실패 → `{401, 'AUTH-900'}`, 호출자가 `allowed`에 없음 → `{403, 'ACL-900'}`(UT-SK-008). 로그·예외 메시지에 토큰 0.

### 4.3 `http-client/http-client.ts` — PeerClient (IF-01 §2.2·§2.9)
- **타입 [T-00-03 Brief §4.2.3과 글자 그대로 동일하게 export]**: `PeerInput` · `PeerCallOptions` · `PeerFailure` · `ResponseOf` · `PeerSuccess` · `PeerClientPort`. (한쪽만 바꾸면 testkit fake와 어긋난다 — 바꿔야 하면 `contract_change`.)
```ts

  readonly clock: Clock; readonly rng?: () => number; readonly httpRequest?: typeof import('node:http').request; readonly metrics?: MetricsRegistry };
export function createPeerClient(opts: PeerClientOptions): PeerClientPort & { circuitState(): 'closed' | 'open' | 'half_open' };
```
- **[Brief 결정]** 피어 1개당 클라이언트 1개(서비스의 `infra/clients/<peer>.client.ts`가 하나씩 만든다), 전송 = `node:http`(keep-alive Agent) — 연결 300ms 타이머를 `'socket'`→`'connect'` 사이에 직접 건다. `baseUrl()`이 null이면 `connect_failed`.
- **사전 검사(결함 → throw)**: `route.path`가 `/internal/v1/`로 시작 · `route.allowedCallers`에 `self` 포함 · `route.idempotent`면 `opts.idempotencyKey`(ULID) 필수 · `input`을 `route.request.{params,query,body}`로 `parse`.
- **데드라인**: `deadlineAt = opts.deadlineAt ?? clock.now() + (route.deadlineMs ?? 2000)`; 매 시도 직전 `remaining = deadlineAt − clock.now() − 10`, ≤ 0이면 호출하지 않고 `deadline_exhausted`. 헤더 `x-fathom-deadline-ms: remaining`, 응답 대기 상한 = `remaining`(초과 `timeout`).
- **헤더**: `authorization: Bearer <token>` · `accept: application/json` · 본문 있으면 `content-type: application/json; charset=utf-8`(본문 = `JSON.stringify`) · `idempotency-key` · `x-request-id: opts.requestId ?? ulid()` · `traceparent`: 입력이 있으면 같은 trace id + 새 span id(`randomBytes(8)` hex) + 같은 flags. 경로 `{name}` = `encodeURIComponent(params[name])`, 콜론 동사는 그대로. 쿼리는 키 정렬, boolean = `'true'|'false'`.
- **응답**: 2xx → 본문(≤ 8 MiB)을 `parseJsonStrict` → `route.response[status]` `safeParse` 성공이면 `ok({status, body, replayed: headers['idempotent-replayed'] === 'true'})`, 스키마 없음·실패 = `contract_violation` · 204면 `route.response[204]`가 있어야 성공(body `null`) · `application/problem+json` → contracts `Problem` 통과 시 `problem`, 아니면 `contract_violation` · 그 밖 비 2xx = `contract_violation`.
- **재시도**(GET 또는 `idempotent`만): `connect_failed`·`connect_timeout`·problem 503·problem 409 + code가 `-CONFLICT-002`로 끝남 → 최대 2회, 대기 100ms·300ms × (0.8 + 0.4·rng()), 대기 후에도 `remaining > 0`일 때만, **같은** `idempotency-key`·`x-request-id`. 대기는 `node:timers/promises`(테스트는 가짜 타이머).
- **서킷**(피어 단위): 연속 연결 실패(`connect_failed`·`connect_timeout`) 3회 → `open` 5000ms → `half_open`에서 시험 호출 1건만 통과(동시 다른 호출 = `circuit_open`) → 성공 `closed`·실패 다시 `open`. open 중 호출 = 즉시 `circuit_open`(요청 0). 연결 외 실패는 카운트하지 않고, 성공은 카운트를 0으로.
- 메트릭(있으면): `peer_call_duration_ms{peer, route}`(route = route id), `peer_circuit_open_total{peer}`.

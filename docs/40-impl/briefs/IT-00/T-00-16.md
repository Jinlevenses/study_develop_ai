#### 4.1.1 경로 · 실행 형태 (`serviceEntry`, `cliInvocation`)
- 서비스 디렉터리 = `{gateway:'gateway', content:'content', learning:'learning', 'ai-gateway':'ai-gateway', 'ops-api':'ops'}`. 진입·execArgv는 **서비스 × 런타임 리터럴 표**(10행 상수, `new URL('services/ops/dist/main.js', appRootUrl)` 형태 — 문자열 결합 0):
  - `dist` → `services/<dir>/dist/main.js`, execArgv `['--disable-warning=ExperimentalWarning']`.
  - `src` → `services/<dir>/src/main.ts`, execArgv `['--disable-warning=ExperimentalWarning', '--import', 'tsx', '--conditions=source']`.
- CLI(`cliInvocation`, bin = `process.execPath`): `dist` → `[...dist execArgv, '<appRoot>/apps/cli/bin/fathom.mjs', ...args]`(= 설치 번들 `fathom` 경로) · `src` → `[...src execArgv, '<appRoot>/apps/cli/src/main.ts', ...args]`(= 루트 `pnpm fathom`·`pnpm dev`와 같은 진입).
- **사전 검사**(spawn 전, `build_missing`): `dist`면 `apps/cli/dist/main.js`·`services/ops/dist/supervisor/main.js`·5개 `services/<dir>/dist/main.js`·`apps/web/dist/index.html` 존재. `src`면 `apps/web/dist/index.html`만(gateway 정적 루트, T-00-12 §9). `egress: 'record'`면 `RECORDER_URL` 파일 존재(`recorder_missing`). `detail` = 빠진 경로 목록 + "`pnpm build` 먼저".

#### 4.1.2 env (`stackEnv`) — ADR-012 §2, D-TST-13
- 새 객체: `PATH`·`HOME`·`LANG`·`LC_ALL`·`TMPDIR`·`TZ`(+ win32 `SYSTEMROOT`) 중 값이 있는 것 + `FATHOM_HOME = home` + (`recorderUrl`이 있으면) `NODE_OPTIONS = '--import=' + recorderUrl`.
- **[Brief 결정]** 러너 자신의 `NODE_OPTIONS`·API 키·`CI`·프록시·`FATHOM_EGRESS_MODE`는 넘기지 않는다(기록기는 `record` 기본 모드 — 차단은 run-offline 탐침만). `recorderUrl`에 공백이 있으면 `recorder_missing`(NODE_OPTIONS는 공백 분리) — 저장소 경로에 공백이 없음을 전제로 한다.
- supervisor가 이 `NODE_OPTIONS`에 `--disable-warning=ExperimentalWarning`을 병합해 모든 서비스·job 자식에 전파한다(T-00-11 §4.1.4). **제품 코드는 손대지 않는다.**

#### 4.1.3 마이그레이션 (`migrateHome`) — T-00-13 §9 ①
- `MIGRATE_ORDER` 순서대로 **직렬**: `spawn(process.execPath, [...execArgv, entry, '--mode=migrate'], { env: stackEnv(...), cwd: appRoot, timeoutMs: 60_000 })`. gateway는 DB가 없으므로 제외. 하나라도 `exitCode !== 0` → 즉시 `migrate_failed`(`svc`·`exitCode`·`stderrTail`·`stdout` 끝 20줄). 결과 배열 반환(E2E-104가 stderr를 검사).

- `pauseService`: win32 → `Error('chaos: unsupported_platform')`. `resume()` 멱등.
- `killService`: `pidOf`가 실패하면 그대로 전파(`not_running`). 재시작 대기는 호출자가 `stack.waitForState(svc, 'ready', { notPid })`.

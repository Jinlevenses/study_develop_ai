- 서명 메시지 = `'v1|' + sid + '|' + port + '|' + iat`(ADR-009 §1-3, 10진 문자열). 파싱 정규식 `^v1\.([A-Za-z0-9_-]{22})\.([1-9]\d{0,4})\.(\d{1,12})\.([A-Za-z0-9_-]{43})$` — 불일치 `malformed`, `port > 65535` `malformed`, mac 불일치(`crypto.equal`) `bad_mac`, `iat > nowS + 300` 또는 `nowS − iat > 34_560_000` → `expired` **[Brief 결정: Max-Age와 같은 서버 측 만료 + 시계 오차 300s]**. 모두 401 `GW-AUTH-003`으로 매핑된다. 포트 대조는 `verifyCookie` 성공 뒤 별도(401 `GW-AUTH-001`).
- `sid` = `base64url(randomBytes(16))`(22자), `iat = Math.floor(clock.now() / 1000)`.


- rate limit: 키마다 `{windowStart, count}`. `nowMs − windowStart ≥ windowMs`면 새 창. `count ≥ max`면 `{allowed: false, retryAfterMs: windowStart + windowMs − nowMs}`. 키 수가 `maxKeys`를 넘으면 창이 끝난 키부터 지우고, 그래도 넘으면 가장 오래된 창의 키를 지운다(메모리 상한).
- 부트스트랩 토큰: 저장 키 = `hash(token)`(원문 미보관), 값 = `expires_at`. `issue` 시 만료된 항목 정리 후 `maxOutstanding` 초과면 가장 이른 만료부터 제거. `consume` = 있음 ∧ `nowMs < expires_at` → 삭제 후 true / 그 외 false(만료 항목도 삭제). 재사용·만료·위조 모두 401 `GW-AUTH-004`.

#### 4.1.4 rate limit 과 `@fastify/*` 사용 여부 **[Brief 결정 — §10 ③]**
- `@fastify/rate-limit`은 Fastify 훅으로 동작해 createService 파이프라인 인증(③~⑤)보다 **먼저** 돌 수 있고 키를 검증된 `sid`로 잡을 수 없다 → IF §2.11 순서 ⑥을 지키려고 `domain/session/guards-rate-limit.ts`를 `publicAuth` 안에서 쓴다(300 req/min/세션·CLI 토큰, NFR-SEC-017 수치 동일). `@fastify/cookie`도 쓰지 않는다(파서가 `readCookie` 한 함수로 충분, 서명 형식이 ADR 고유).

#### 4.1.6 SSE 허브 (`application/stream/`) — IF §2.13, IR-016

```ts
export type SseClient = { write(chunk: string): boolean; close(): void };
export interface SseHub {
  attach(o: { readonly bootId: string; readonly appVersion: string; readonly clock: Clock }): void;   // registerStream에서 1회
  publish(events: readonly IntegrationEventEnvelope[]): void;                // notify inbox 콜백
  open(client: SseClient, o: { readonly sid: string; readonly lastEventId: string | undefined }): Result<() => void /* 해제 */, 'too_many'>;
  activeStreams(): number; closeAll(): void;
}
export function createSseHub(o: { readonly ring: number; readonly heartbeatMs: number; readonly retryMs: number; readonly maxPerSession: number }): SseHub;
```
- **링**(`ring.ts`): 항목 `{seq, event_id, type, data /* JSON 한 줄 */}`, 용량 1,000, 넘으면 가장 오래된 것 폐기. `hub_seq`는 1부터 단조 증가(메모리, 재시작 시 0부터). 같은 `event_id`가 링에 있으면 publish에서 버림(링과 같은 수명의 `Set`, 폐기 시 함께 삭제).
- **publish**: 이벤트마다 `SseEventData.parse({type, schema_version, event_id, occurred_at, correlation_id, producer, payload})` → 링 저장 → 연결 전원에 프레임 송신. `type === 'ai.mode.changed'`면 `payload.mode`가 `AiMode` 통과 시 `lastAiMode` 갱신(초기값 `'OFFLINE'` — FR-AI-003 첫 기동) **[Brief 결정]**. attach 전 publish = `invariant`.
- **프레임**(`frames.ts`): 데이터 프레임 = `id: <boot>.<seq>\nevent: <type>\ndata: <json>\n\n` · heartbeat = `: hb <epoch_ms>\n\n` · 첫 출력 = `retry: 2000\n\n`.
- **open 순서**: 세션당 연결 수 ≥ 8 → `too_many`(라우트가 429 `GW-LIMIT-002`) → `retry` → **hello**(`id: <boot>.<resume>`, `event: hello`, `data: SseHello{boot_id, hub_seq: resume, server_time, app_version, ai_mode: lastAiMode}`) → 재연결 판정 → heartbeat 타이머(15s, unref) 시작.
  - `Last-Event-ID` 파싱 `^([0-9A-HJKMNP-TV-Z]{26})\.(\d{1,15})$`: 없음 → `resume = head`(재전송 0) · 형식 오류 또는 `seq > head` → `resync{reason:'unknown_last_event_id'}` · boot 다름 → `resync{'gateway_restarted'}` · 같은 boot이고 `seq < oldest − 1`(링 밖) → `resync{'ring_overflow'}` · 그 밖 → `resume = seq`, hello 뒤에 `seq` 초과 항목을 순서대로 재전송.
  - resync 프레임 = `id: <boot>.<head>\nevent: resync\ndata: <SseResync>\n\n`(hello의 `resume`도 `head`). **[Brief 결정]** hello의 `id`·`hub_seq` = 재전송 시작점 — 재전송 도중 끊겨도 브라우저의 `Last-Event-ID`가 앞서 가지 않는다.
- **라우트**(`http/stream/routes.ts`): `app.stream(StreamOpenRoute, handler)` — `sid` 재검증(§4.1.3) → `hub.open` 실패 → `AppError('GW-LIMIT-002', 429)`(하이잭 **전**) → `reply.hijack()` → `reply.raw.writeHead(200, {'content-type': 'text/event-stream; charset=utf-8', 'cache-control': 'no-store', 'x-accel-buffering': 'no', 'x-request-id': ctx.requestId})` → `client.write = (s) => reply.raw.write(s)` → `reply.raw.on('close', 해제)` + `'error'` 리스너(STD-ASY-10). 쓰기 실패·close → 해제(타이머 정리, 카운트 감소).
- `registerStream`: `ctx.hub.attach({bootId: deps.bootId, appVersion: deps.appVersion, clock: deps.clock})` · `deps.onShutdown(() => ctx.hub.closeAll())`(진행 중 SSE를 fastify.close 전에 끊음).
- `manifest.ts`: `gatewayManifest(): ConsumerManifest` = `ConsumerManifest.parse({consumer: 'gateway', subscriptions: Object.entries(SUBSCRIPTIONS.gateway).map(([type, s]) => ({type, ...s}))})` — 17구독·전부 notify/drop(UT-GW-062).

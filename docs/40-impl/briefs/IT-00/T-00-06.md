## 4. 동작 규약

### 4.1 모든 게이트 공통

1. T-00-05 Brief §4.1.1 계약 그대로: `runGate({id, requireUnits, spec}, fn)`, 종료 코드 0/1/2, 진단 `{file, line, rule, message, severity}`, `--root`·`--json`·`--quiet`, 결정적 정렬. id는 `lib/registry.mjs`의 `GATES[].id`와 같아야 한다(예: `check-security-scan.mjs`의 id = `check:security`, `check-hooks.mjs` = `lint:hooks`, `check-graphify-edges.mjs` = `audit:graph`).
2. 구조: 각 파일은 `export async function analyze(root, opts)` → `{files, violations, extra?}`를 두고 `if (isMain(import.meta.url)) runGate(meta, (o) => analyze(o.root, o))`. 테스트는 `analyze`를 직접 부르거나 스크립트를 `spawnSync(process.execPath, …)`로 실행한다.
3. **공유 헬퍼 위치 [Brief 결정]**: SQL 문자열 수집 `export function sqlLiterals(tokens)` → `[{text, line}]`(문자열·`${}` 없는 템플릿 토큰 각각 + `+`로만 이어진 리터럴 사슬을 이어 붙인 것)과 `export function normalizeSql(text)`(공백 1칸·대문자화한 비교용 문자열)는 `check-sql-template.mjs`에 두고 `check-db-paths`·`check-ledger-writer`·`check-content-ingest`가 import. 소스 파일 목록 `export function srcFiles(root, exts)`(= `walk(root, {exts, include: ['apps/*/src/**', 'services/*/src/**', 'packages/*/src/**', 'tools/*/src/**']})`)는 `check-security-scan.mjs`에 두고 다른 게이트가 import.
4. **스캔 범위 기본값**: "src" = 위 `srcFiles` include. 게이트별 예외는 각 절에 적는다. `walk`의 기본 제외(T-00-05 §4.1.1)는 항상 적용.
5. **설정 파일**: `--config <path>` 옵션, 기본 = `new URL('./config/<name>.json', import.meta.url)`(게이트 위치 기준 — fixture도 실제 설정을 쓴다). 읽기·파싱 실패·`version !== 1`·필수 키 누락 → exit 2(`engine/config`).
6. **fixture**: 게이트마다 `tools/gates/fixtures/<script 이름>/{clean,violations}/`(+ 회피가 있으면 `evasions/`), T-00-05 §4.1.5 규약(`selftest.args.json`의 `"${CASE}"`, 주석 불가 파일의 기대값은 `expect.json`, `EXPECT[...]`·`EXPECT-NEXT[...]`·`EVADES[...]` 마커). `requireUnits: true` 게이트의 fixture는 `services/<x>/`·`packages/contracts/` 디렉터리를 가진다(빈 디렉터리는 `.gitkeep`). **빈 root → 2**가 성립하도록 `requireUnits: false` 게이트는 필수 입력 파일(아래 각 절)을 root 기준으로 찾는다. fixture 가짜 비밀은 `x` 채움만(예: `sk-ant-xxxxxxxxxxxxxxxxxxxxxxxx`) — 실제처럼 보이는 난수 문자열 금지(push protection).
7. **규칙 ID 정본**: ADR-010 §5 형식 `<family>/<rule>`. DS-01 §13 표에 이름이 있는 규칙은 **그 이름**을 쓴다(SP-7 이름과 다르면 DS-01 우선, §4.4.1 대응표).

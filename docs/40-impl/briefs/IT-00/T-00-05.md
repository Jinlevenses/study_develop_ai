## 4. 동작 규약

### 4.1 WP-00-10 — 게이트 코어

#### 4.1.1 모든 게이트 공통 계약 (T-00-06 게이트에도 적용)

| 항목 | 규약 |
|---|---|
| 실행 | `node tools/gates/<script>.mjs [--root <dir>] [--json] [--quiet] [게이트별 옵션]`. `--root` 기본 = cwd, `path.resolve` 후 사용 |
| 종료 코드 | `0` 통과(오류 0, 경고는 허용) · `1` 위반(severity `error` ≥ 1) · `2` 엔진 고장 |
| exit 2 사유(전부) | 최상위 예외 · **스캔 파일 0개**(`engine/no-files`) · 기대 단위 부재(`engine/missing-units`: `<root>/services/` 하위 디렉터리 ≥ 1 **그리고** `<root>/packages/contracts/` 존재 — 단위 검사 게이트만) · root 없음(ENOENT) · 설정 파일 부재·JSON 파싱 실패·스키마 위반 · tsgo 초기화 실패(typescript 해석 실패·프로젝트 열기 실패·프로젝트 파일 0개) · 필수 입력 파일 부재 · 알 수 없는 플래그·필수 옵션 누락 |
| 진단 | `{file, line, rule, message, severity}` — `file` = root 기준 posix 상대 경로(파일 없는 저장소 단위 진단은 `"(repo)"`, `line: 0`), `rule` = `<family>/<rule>`, `severity` ∈ `error`·`warn` |
| `--json` 출력 | stdout 마지막 줄 1개: `{"check":"<id>","root":"<abs>","exit":0,"files":N,"errors":N,"warnings":N,"violations":[…],…extra}`. exit 2이면 `{"check","root","exit":2,"error":"<사유 코드>: <메시지>"}` |
| 텍스트 출력 | 진단 1건 = 1줄 `<file>:<line>  <severity>  <rule>  <message>`, 마지막 줄 `[<id>] <e> error(s), <w> warning(s), <n> file(s)`. `--quiet`이면 마지막 줄만. exit 2 사유는 stderr 1줄 `[<id>] engine error: <사유 코드>: <메시지>` |
| 정렬·중복 | `file`→`line`→`rule` 사전순 정렬, 같은 `(file,line,rule)`은 1건 |
| 탈출구 | 같은 줄 또는 **바로 윗줄**의 주석 `// <tag>: <사유>`(사유 = 공백 제외 1자 이상). 사유 없으면 무효(진단 유지). tag ∈ `boundary-ok`·`sql-ok`·`jev-ok`, 그리고 `biome-ignore lint/plugin: <사유>`(sql·ng-g·typo 계열 게이트가 허용 여부를 결정) |
| 스캔 제외(STD-GATE-04 + [Brief 결정]) | 디렉터리 이름 `node_modules`·`.git`·`dist`·`build`·`coverage`·`.turbo`·`graphify-out`·`.fathom-dev`·`playwright-report`·`test-results`·`.reports` · 경로 glob `spikes/**`·`docs/**`·`tools/gates/**`(게이트 엔진·fixture·테스트 — 자기 검증은 selftest)·`tools/packc/fixtures/**`·`**/test/fixtures/**` |
| 결정성 | 파일 목록 정렬, 시계·난수 미사용, 같은 입력 = 같은 출력 바이트 |
| 성능(참고) | tokens 게이트 ≤ 250ms·`both` ≤ 1s(822파일 기준, ADR-010 §11) — 테스트로 강제하지 않음 |

#### 4.1.3 `check-boundaries.mjs` + `config/boundaries.json`

- 옵션: `--engine=tokens|tsgo|both`(기본 `tokens` — CI·run-gates는 `both`를 명시) · `--config <path>`. `requireUnits: true`.

#### 4.1.4 `run-gates.mjs` (`pnpm check:gates`)

- 옵션: `--stage=g1|g2|g3`(기본 `g2`, **누적**: g2 = g1 ∪ g2) · `--warn-only` · `--allow-tokens-only` · `--allow-missing` · `--task <T-nn-mm>` · `--int <INT-id>` · `--base <ref>` · `--json` · `--root` · 테스트 전용 `--registry <json 파일>`(GATES 대체: 같은 필드 배열)·`--gates-dir <dir>`(스크립트 위치, 기본 = run-gates.mjs가 있는 디렉터리).
- 사전 검사: `<root>/tsconfig.json` 없으면 **exit 2**(`engine/tsgo: tsconfig.json missing — use --allow-tokens-only for local diagnosis`). `--allow-tokens-only`면 stderr 경고 1줄 후 `check:boundaries`를 `--engine=tokens`로, `check:sql-typed`는 `skipped(tokens-only)`.
- 실행 순서: g1이면 먼저 `check-gate-selftest.mjs`(`--allow-missing` 전달) → 레지스트리 순서대로 해당 단계 게이트. `check:scope`는 `--task`가 있을 때만(`--task`·`--base` 전달). `check:frozen`에는 `--task`·`--base`가 있으면 전달. `check:manifest`·`check:rtm`에는 `--int` 전달, **g3인데 `--int` 없으면 exit 2**(`engine/usage`). `--int`가 `INT-7`·`PG-3`이 아니면 `check:manifest`에 `--schedule tests/e2e/mode-schedule.json`도 전달(WBS D-WBS-09).
- 자식 실행: `spawnSync(process.execPath, [script, '--root', root, '--json', '--quiet', ...args], {encoding: 'utf8', timeout: 120_000, maxBuffer: 64 * 1024 * 1024})`. stdout 마지막 줄 JSON 파싱(실패 = 그 게이트 exit 2로 취급). 타임아웃 = 2.
- 스크립트 파일 없음: `--allow-missing`이면 `skipped(missing)` + stderr 경고, 아니면 그 게이트 = 2.
- 집계: 어느 하나라도 2 → **2** · 아니면 `error` 진단이 있는 게이트(exit 1)가 있으면 1 · 아니면 0. **`--warn-only`**: 1을 0으로 바꿔 보고(위반 목록은 그대로 출력), **2는 그대로 2**(ADR-010 §10, C-04).
- 출력: 게이트당 1줄 `PASS|FAIL|WARN|ERROR|SKIP  <id padEnd 22>  errors=<n> warnings=<n> files=<n>  <ms>ms` (`WARN` = warn-only로 강등된 실패, `ERROR` = exit 2) + 마지막 줄 `[check:gates] stage=<s> exit=<n>`. `--json`: `{"stage","warn_only","exit","gates":[{"id","script","exit","errors","warnings","files","ms","skipped"?:"missing"|"tokens-only","error"?}]}`.

#### 4.1.5 `check-gate-selftest.mjs` (`check:gate-selftest`) — fixture 규약 **[Brief 결정 — T-00-06 fixture도 이 규약]**

- 대상: `GATES`의 각 항목(`audit:graph` 포함). 스크립트 없음 → `--allow-missing`이면 `skipped`, 아니면 exit 2.
- fixture 배치: `tools/gates/fixtures/<fixture>/{clean, violations, evasions?}/` — 각 케이스 디렉터리가 **하나의 가짜 저장소 root**다. 케이스 디렉터리에 선택 파일 `selftest.args.json`(문자열 배열, `"${CASE}"` 토큰은 케이스 절대 경로로 치환)이 있으면 기본 args 뒤에 붙인다. `selftest.args.json`·`expect.json`은 게이트 스캔 대상에서 빠지도록 게이트가 무시한다(`walk`의 기본 제외가 아니라 이름 비교로 — §4.1.2 `walk`에 `SELFTEST_FILES = ['selftest.args.json', 'expect.json']` 제외 추가).
- 단언(게이트마다): ① `clean` → exit **0** ② `violations` → exit **1** 이고, `loadExpectations` 결과가 비어 있지 않으면 보고 집합 `{file:line:rule}`(severity `error`만) = 기대 집합(누락·초과 0) ③ 빈 임시 디렉터리를 root로(같은 케이스 args 사용, clean 기준) → exit **2** ④ 존재하지 않는 경로를 root로 → exit **2** ⑤ `evasions`(있으면) → 실행만 하고 `EVADES[...]` 행을 보고서에 "한계"로 기록(통과 기준 아님, ADR-010 §3).
- fixture 디렉터리 자체가 없는 게이트(스크립트는 있음) → 진단 `selftest/fixture-missing`(exit 1, STD-TST-11).
- 위반 진단: `selftest/clean-not-zero` · `selftest/violations-not-one` · `selftest/expect-mismatch`(메시지에 fp·fn 목록) · `selftest/empty-root-not-two` · `selftest/missing-root-not-two`. `file` = `tools/gates/fixtures/<fixture>/<case>`.
- 옵션: `--allow-missing` · `--only <id>` · `--json` · 테스트 전용 `--registry`·`--gates-dir`·`--fixtures-dir`. 이 게이트는 `requireUnits: false`, 검사한 게이트 수 0 → exit 2.

- `snapshot.ts`: `computeMetrics(graph, {intId, createdAt, graphifyVersion, commit, audit})` → STD §18.4 형식 **키 순서 그대로**: `int_id, created_at, graphify_version, commit, nodes, edges, communities, nodes_by_unit, god_nodes_top10, cross_service_edges, cross_service_edge_count, audit_graph`. `communities` = 노드 `community` 속성의 서로 다른 값 수(속성 없으면 0). `nodes_by_unit` = `source_file`의 단위(`apps/<n>`·`services/<n>`·`packages/<n>`·`tools/<n>`·`tests`)별 수, 키 사전순, 단위 없는 노드는 제외. `cross_service_edges` = relation ∈ {`imports_from`, `re_exports`, `dynamic_import`, `imports`} ∧ target id가 `ref_`로 시작하지 않음 ∧ source 파일이 `package.json` 아님 ∧ 양 끝 단위가 모두 `services/*` 또는 `apps/*`이고 서로 다름 → `{from, to, relation}`(from/to = source_file), (from,to,relation) 중복 제거·사전순.
- `cli.ts`: `snapshot --int <id> [--root .] [--graph graphify-out/graph.json] [--out docs/40-impl/graph]`(첫 인자가 `--`면 `snapshot`) → `<out>/<id>/metrics.json`(2칸 들여쓰기 + 끝 줄바꿈) + `<root>/graphify-out/GRAPH_REPORT.md`가 있으면 `<out>/<id>/GRAPH_REPORT.md`로 복사. graph 파일 없음 → exit 2(`graph missing — run graphify update . first`). `graphify_version` = `execFileSync('graphify', ['--version'])`의 첫 semver, 실패(ENOENT 포함) → `"unavailable"`. `commit` = `git rev-parse HEAD`, 실패 → `"unknown"`. `audit_graph` = `<root>/tools/gates/check-graphify-edges.mjs`가 있으면 `execFileSync(process.execPath, [script, '--root', root, '--graph', graph, '--json'])`의 exit → `{exit, skipped: false}`, 스크립트 없음 → `{exit: null, skipped: true}`. `god-nodes [--top 10] [--graph] [--json]` → 표 또는 JSON 출력. `--int` 형식은 §4.3.2와 같음.
- 시계·외부 호출은 cli에서만 주입(테스트는 고정 `createdAt`·가짜 버전).

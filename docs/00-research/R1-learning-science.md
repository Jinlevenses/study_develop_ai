## 0. 요약 (Executive Summary)

1. **핵심 엔진은 "인출(Retrieval) × 간격(Spacing) × 적정 난이도(Desirable Difficulty)"** 이다. Dunlosky et al.(2013)의 10대 학습법 평가에서 *High utility*는 **Practice testing**과 **Distributed practice** 두 개뿐이다. 서비스의 모든 모드(OX, 문제, 백지노트, 개념 디깅)는 결국 "인출 이벤트"를 만들어 **스케줄러(FSRS)** 와 **숙달 모델(Elo/BKT)** 에 먹이는 구조여야 한다.
2. **이중 모델(Dual-model) 권고**: (a) *기억 유지*는 FSRS-6(개념 카드 단위, Knowledge Component=KC), (b) *기능 숙달*은 Elo(학습자 θ × 문항 β) + 선택적 BKT. FSRS는 "잊을 확률"을, Elo는 "풀 수 있는 난이도"를 답한다. 둘을 혼동하면 절차적 스킬(코드 작성)을 플래시카드처럼 다루는 실수를 하게 된다.
3. **스케줄 단위는 '문항'이 아니라 'KC(개념)'**, 출제는 KC별 **문항 풀에서 매번 다른 변형(variant)** 을 뽑는다. 동일 문항 반복은 표면 암기(“이 문제 답은 B”)로 붕괴한다. → UR-13 문제 생성 로직의 존재 이유.
4. **수준(L1~L5)에 따라 학습법 믹스가 바뀌어야 한다**(Expertise Reversal Effect). L1은 Worked example·Parsons·OX가 효과적이지만 L4~L5에게는 오히려 역효과. L4~L5는 사례 분석·트레이드오프 판단·설계 리뷰·가르치기(Feynman)·대조 사례가 중심.
5. **채점 계층(Grading Ladder)**: 결정적 채점(정답키·테스트·순서 비교) > **Jev 판단**(noul/choice/score: 루브릭, 오개념 탐지, SOLO 수준) > LLM-as-judge(해설 필요 시) > 자기평가(+보정 추적). LLM은 *생성*(문제·해설·소크라테스 질문), Jev는 *판단*(채점·분류·다음 단계 라우팅)으로 역할 분리 (UR-16).
6. **질림 방지**는 "게임 요소"가 아니라 **(i) 성공률 70~85% 대역 유지(flow channel), (ii) 모드 로테이션(novelty), (iii) 번아웃 없는 주간 목표형 스트릭, (iv) 역량 가시화(스킬맵)** 로 달성한다. 리더보드·포인트 인플레이션·손실회피형 스트릭은 배제.

## 1. 분석 프레임: 지식 유형 × 수준 × 활동 모드

### 1.1 지식 유형 (Anderson & Krathwohl 2001, Bloom 개정판의 Knowledge dimension + 개발 도메인 확장)

| 코드 | 지식 유형 | 개발 도메인 예시 | 주 학습 메커니즘 |
|---|---|---|---|
| K-F | **Factual / Declarative** (사실) | HTTP 상태코드 의미, `kubectl` 서브커맨드, OWASP Top 10 항목명 | 인출 + 간격 반복 |
| K-C | **Conceptual** (개념·원리·모델) | CAP 정리, 이벤트 루프, TCP 혼잡제어, Attention 메커니즘, 트랜잭션 격리수준 | 설명 생성(자기설명·정교화), 개념맵, 대조 사례 |
| K-P | **Procedural** (절차·기능) | 이진탐색 구현, Dockerfile 멀티스테이지 작성, CI 파이프라인 구성, 디버깅 | Worked→Faded example, 반복 연습, 즉각 피드백 |
| K-M | **Metacognitive** (메타인지) | "내가 무엇을 모르는지", 학습 전략 선택, 보정(calibration) | 확신도 표시, 백지 복습 후 diff, 회고 |
| K-S | **Strategic / Judgment** (도메인 판단; 개발 확장) | 모놀리스 vs MSA 결정, 장애 대응 우선순위, 보안 위협 모델링, LLM 평가 설계 | 사례 기반 추론, 트레이드오프 분석, 설계 리뷰, 포스트모템 |

> K-S는 Bloom 원 분류에는 없지만, 15년차 전문가의 핵심 역량(“it depends”를 구조화하는 능력)이므로 별도 유형으로 둔다. Jev의 `score`/`choice`가 가장 가치 있게 쓰이는 영역이다.

### 1.2 수준 모델 L1~L5 (Dreyfus 5단계 × 경력 × Bloom × SOLO 정렬)

| 레벨 | Dreyfus (1980) | 경력 가정 | 행동 특성 | Bloom 인지과정 주력 | SOLO 목표 | 적합한 학습 형태 |
|---|---|---|---|---|---|---|
| **L1 입문** | Novice | 0–1년 | 맥락 없는 규칙을 따름, 용어 부족 | Remember, Understand | Uni- → Multistructural | Worked example, OX, 플래시카드, Parsons, 이중부호화 |
| **L2 초급** | Advanced Beginner | 1–3년 | 상황적 요소 인식, 가이드 하 독립 구현 | Understand, Apply | Multistructural | Faded example, 코드 추적(predict), 짧은 구현, 자기설명 |
| **L3 중급** | Competent | 3–6년 | 목표·계획 수립, 우선순위, 책임감 있는 선택 | Apply, Analyze | Relational | 교차 연습, 디버깅, 정교화 질문, 개념맵, 백지 복습 |
| **L4 고급** | Proficient | 6–10년 | 전체 상황을 통째로 봄, 패턴 인식, 직관적 이상 감지 | Analyze, Evaluate | Relational → Extended abstract | 사례·장애 분석, 설계 리뷰, 대조 사례, 소크라테스 디깅 |
| **L5 전문가** | Expert | 10–15년+ | 직관적 판단 + 필요 시 분석, 새로운 문제 정의, 표준 수립 | Evaluate, Create | Extended abstract | 설계 과제·ADR 작성, 가르치기(Feynman), 생산적 실패, 경계조건 탐구 |

- **레벨은 사용자 전체가 아니라 `(섹션 × KC)` 단위로 부여**한다. 15년 로드맵에서 "프론트는 L4인데 보안은 L2"가 정상이다. UR-01의 섹션 분리와 UR-11의 깊이는 **2차원 좌표(섹션, 레벨)** 로 관리.
- 레벨 승급 조건은 §7(숙달 기준)에서 정의.

### 1.3 ICAP 프레임워크 (Chi & Wylie, 2014) — 모드 설계의 상위 원칙

학습 활동의 인지적 관여도: **Interactive > Constructive > Active > Passive** (근거 B+). 
- Passive: 읽기·영상 시청 → 서비스에서 최소화, "이론" 단계조차 인출 질문을 삽입(pre-question, embedded quiz).
- Active: 하이라이트, 코드 따라 치기 → 보조 수단.
- Constructive: 자기설명, 백지노트, 개념맵, 코드 작성 → 주력.
- Interactive: AI 튜터와 소크라테스 대화, AI "헷갈리는 학생"에게 가르치기 → 고급 모드.

**설계 원칙**: 모든 세션은 최소 60% 이상을 Constructive/Interactive 활동으로 채운다(세션 템플릿 §10).

### 1.4 UR-10(이론 → 코드 → 핵심 개념) 3단계와 학습법 매핑

| 단계 | 목적 | 주 학습법 | 산출 이벤트 |
|---|---|---|---|
| ① 이론(Theory) | 정신 모델 형성 | Pre-question(사전 인출), 이중부호화 설명, 정교화 질문, 예제 기반 설명 | 이해도 체크(ICAP-Active→Constructive) |
| ② 코드(Code) | 절차적 전이 | Worked → Faded example, Parsons, Predict-Run-Investigate-Modify-Make(PRIMM), 디버깅 | 숙달 모델(Elo) 업데이트 |
| ③ 핵심 개념(Core Concept) | 장기 보존·연결 | 인출 연습(카드/OX/단답), 백지 복습, 개념 디깅, 개념맵 | FSRS 카드 생성·스케줄 |

→ ③의 결과물이 FSRS 카드로 "적립"되고, 이후 리뷰 세션에서 교차(interleaving)·변형되어 재등장하는 흐름이 서비스 코어 루프다.

## 2. 기억·인출 계열

### 2.1 Retrieval Practice (인출 연습, Testing Effect)

- **메커니즘**: 기억에서 꺼내는 행위 자체가 인출 경로를 강화(retrieval-induced consolidation)하고, 실패 시 후속 학습의 부호화를 강화(test-potentiated learning). 재독(rereading)은 유창성 착각(fluency illusion)을 만든다.
- **근거**: **A**. Roediger & Karpicke(2006): 1주 후 파지에서 반복 시험 조건이 반복 학습 조건보다 크게 우수. Rowland(2014) 메타분석 g ≈ 0.50, Adesope et al.(2017) g ≈ 0.61. Karpicke & Blunt(2011): 인출 연습이 개념맵 작성보다 추론형 문항에서도 우수. 피드백이 붙으면 효과 증가.
- **적합**: K-F·K-C 매우 강함. K-P는 "문제 풀기 = 인출"로 간주 가능. 전 레벨(L1~L5), 단 문항의 인지 수준을 레벨에 맞춰 상향.
- **주의**: 인출 난이도가 너무 높아 실패율이 과도하면(<50%) 피드백 없이는 역효과. **즉시 정답 피드백 + 해설** 필수. 객관식은 오답 선택지(lure)를 사실로 기억하는 부정적 시험효과가 있으므로 **해설에서 오답 선택지를 명시적으로 교정**.
- **UX**:
  - "읽기 전에 먼저 맞혀보기(Pre-question)" 카드 1~3개를 이론 페이지 상단에 배치(오답이어도 이후 학습 향상: pretesting effect, 근거 B).
  - 답 입력 → **확신도 선택(§5.1)** → 공개 → 자기/자동 채점 → 해설. 답 공개 전 "생각 중" 최소 시간(예: 3초) 동안 공개 버튼 비활성화로 "그냥 보기" 방지.
  - 문항 형식 다양화: 단답, 빈칸(cloze), 코드 출력 예측, 개념 → 예시 생성, 예시 → 개념 명명.

### 2.2 Spaced Repetition (간격 반복) — FSRS 상세

- **메커니즘**: 간격 효과(spacing effect)—망각이 일부 진행된 시점의 인출이 더 큰 안정성 증가를 낳는다(“study-phase retrieval”, “reconsolidation”). Cepeda et al.(2006) 메타분석(254개 연구, 근거 **A**), Cepeda et al.(2008): 최적 간격은 목표 보존 기간의 약 10~20%.
- **적합**: K-F·K-C 최강, K-P에도 유효(분산 연습 > 집중 연습). 전 레벨. L4~L5는 "카드"보다 "사례 문제"를 간격 반복.

#### 2.2.1 SM-2 (SuperMemo 2, 1987; Anki 레거시)

- 등급 q ∈ {0..5}. 쉬움계수 `EF' = EF + (0.1 − (5−q)(0.08 + (5−q)·0.02))`, 하한 1.3. q < 3이면 반복 횟수 리셋.
- 간격: I(1)=1일, I(2)=6일, I(n)=I(n−1)·EF.
- **한계**: (1) 기억 상태를 확률로 표현하지 않음(“지금 기억할 확률”을 모름) → 목표 보존율 설정 불가. (2) "Ease hell": 오답이 누적되면 EF가 1.3에 갇혀 영원히 짧은 간격. (3) 연체(overdue) 리뷰의 가치를 반영하지 못함. (4) 개인화 파라미터 학습 없음.

#### 2.2.2 FSRS (Free Spaced Repetition Scheduler) — DSR 모델

Jarrett Ye(叶峻峣) 등이 개발한 오픈소스 스케줄러. Anki 23.10+ 기본 옵션. 이론 기반은 **DSR(Difficulty–Stability–Retrievability) 3성분 기억 모델**(Woźniak의 2성분 모델 확장).

| 변수 | 정의 | 범위 |
|---|---|---|
| **R (Retrievability)** | 지금 이 순간 인출에 성공할 확률 | 0~1 |
| **S (Stability)** | R이 100%→90%로 떨어지는 데 걸리는 일수. 즉 R(t=S)=0.9 | 0.001 ~ 36500일 |
| **D (Difficulty)** | 해당 항목의 본질적 난이도. S 증가폭을 조절 | 1~10 |

등급 G: **1=Again(실패), 2=Hard, 3=Good, 4=Easy**.

**(1) 망각곡선 (Power-law)**
- `R(t, S) = (1 + FACTOR · t / S) ^ (−w20)`, `FACTOR = 0.9^(−1/w20) − 1` → 항상 R(S, S) = 0.9.
- FSRS-5: w20(decay) 고정 0.5, FACTOR = 19/81. **FSRS-6: decay가 학습 가능한 파라미터 w20**(기본 0.1542, 범위 0.1~0.8)로 개인별 곡선 형태를 맞춘다.

**(2) 다음 간격** — 목표 보존율 r(desired retention)에서 역산
- `I(r, S) = (S / FACTOR) · (r^(1/(−w20)) − 1)`, 반올림, 최소 1일, 최대 `maximum_interval`(기본 36500).
- FSRS-6 기본값 기준 계산(직접 계산):

| desired retention r | 간격 I (S의 배수) | 해석 |
|---|---|---|
| 0.95 | ≈ 0.40 S | 복습량 급증 |
| **0.90 (기본)** | **= 1.00 S** | 표준 |
| 0.85 | ≈ 1.91 S | 복습량 약 절반 수준 |
| 0.80 | ≈ 3.31 S | 망각 허용 증가 |

**(3) 초기값** (첫 평가 G)
- `S0(G) = w[G−1]` → FSRS-6 기본: Again 0.212 / Hard 1.2931 / Good 2.3065 / Easy 8.2956 (일).
- `D0(G) = w4 − e^(w5·(G−1)) + 1`, [1,10]으로 clamp. (예: Good → 6.4133 − e^(1.6668) + 1 ≈ 2.12)

**(4) 난이도 갱신** (선형 감쇠 + 평균 회귀)
- `ΔD = −w6 · (G − 3)`
- `D' = D + ΔD · (10 − D) / 9` (10에 가까울수록 증가폭 감소 → ease hell 방지)
- `D'' = w7 · D0(4) + (1 − w7) · D'` (Easy 초기난이도로 평균 회귀), [1,10] clamp.

**(5) 성공 시 안정성 갱신 (G ∈ {2,3,4})**
- `S'_r = S · (1 + e^(w8) · (11 − D) · S^(−w9) · (e^(w10·(1−R)) − 1) · (G=2 ? w15 : 1) · (G=4 ? w16 : 1))`
- 해석: ① D가 높을수록 증가폭↓, ② S가 이미 클수록 증가폭↓(포화), ③ **R이 낮을 때(많이 잊었을 때) 성공하면 증가폭↑** = desirable difficulty의 수식화.
- 예(직접 계산): 신규 카드 Good(S=2.31, D=2.12) → 2일 후 R≈0.9에서 Good → **S' ≈ 11.9일**.

**(6) 실패 시 안정성 (G = 1, lapse)**
- `S'_f = min( w11 · D^(−w12) · ((S+1)^(w13) − 1) · e^(w14·(1−R)),  S / e^(w17·w18) )` — 실패 후 S가 이전보다 커지지 않도록 상한.

**(7) 당일(단기) 리뷰** (학습 단계 중 같은 날 재평가)
- `S' = S · e^(w17·(G − 3 + w18)) · S^(−w19)` (FSRS-6에서 `S^(−w19)` 항 추가, G≥2이면 증가배수 ≥ 1로 clamp).

**(8) FSRS-6 기본 파라미터 (21개, py-fsrs/ts-fsrs 소스 확인)**
```
w = [0.212, 1.2931, 2.3065, 8.2956, 6.4133, 0.8334, 3.0194, 0.001,
     1.8722, 0.1666, 0.796, 1.4835, 0.0614, 0.2629, 1.6483, 0.6014,
     1.8729, 0.5425, 0.0912, 0.0658, 0.1542]
desired_retention = 0.9, learning_steps = [1m, 10m], relearning_steps = [10m],
maximum_interval = 36500, fuzz: py-fsrs 기본 on / ts-fsrs 기본 off
fuzz 범위: 2.5–7일 ±15%, 7–20일 ±10%, 20일+ ±5%
```
- FSRS-5 기본 파라미터(19개, decay 0.5 고정; 작성자 기억 기반 — 구현 시 라이브러리 상수로 재확인):
  `[0.40255, 1.18385, 3.173, 15.69105, 7.1949, 0.5345, 1.4604, 0.0046, 1.54575, 0.1192, 1.01925, 1.9395, 0.11, 0.29605, 2.2698, 0.2315, 2.9898, 0.51655, 0.6621]`
- **권고: FSRS-6 채택**. 이유: decay 학습으로 개인 곡선 적합 개선, 당일 리뷰 모델 개선, 현재 두 공식 라이브러리의 기본값.

**(9) SM-2 vs FSRS 비교**

| 항목 | SM-2 | FSRS-6 |
|---|---|---|
| 기억 상태 표현 | EF + 간격 (확률 없음) | D, S, R (확률 모델) |
| 목표 보존율 설정 | 불가 | 가능(0.7~0.97 권장 범위) |
| 연체 리뷰 처리 | 무시 | R이 낮을수록 성공 보상↑ |
| Ease hell | 있음 | 평균회귀·선형감쇠로 완화 |
| 개인화 | 없음 | 리뷰 로그로 파라미터 최적화(Optimizer) |
| 예측 성능 | 기준선 | open-spaced-repetition `srs-benchmark`에서 SM-2 대비 log-loss·RMSE 크게 우수, 동일 보존율에서 복습량 약 20~30% 절감 보고(재확인 필요) |
| 구현 복잡도 | 20줄 | 150~250줄 또는 라이브러리 |

#### 2.2.3 스케줄러 구현 방안 (아키텍처 입력)

- **라이브러리**: Node 스택이면 `ts-fsrs@5.x`(MIT, 의존성 가벼움, Node ≥ 20, FSRS-6) 채택 권고. 도메인 코드는 `SchedulerPort` 인터페이스 뒤에 감싸 교체 가능하게(FSRS-7 등 대비). Python 서비스라면 `fsrs`(py-fsrs 6.x). 파라미터 최적화는 `fsrs[optimizer]`(PyTorch 필요) 또는 `fsrs-rs` 기반 도구를 **오프라인 배치 작업**으로만 실행.
- **데이터 모델(개념)**:
  - `srs_card(card_id, kc_id, facet, state{New|Learning|Review|Relearning}, stability, difficulty, due_at, last_review_at, step, reps, lapses, desired_retention_override, suspended)`
  - `review_log(id, card_id, item_id(실제 출제 문항), rating, reviewed_at, elapsed_days, scheduled_days, duration_ms, mode(OX|cloze|blank|…), grader(deterministic|jev|llm|self), confidence, raw_score)` — **리뷰 로그는 불변(append-only)**. 파라미터 재최적화·리플레이의 원천.
- **카드 단위 = KC × facet**: facet 예) `definition`(정의), `mechanism`(작동 원리), `tradeoff`(장단점), `code`(코드 패턴), `pitfall`(흔한 실수). 한 KC가 3~5개 카드를 가질 수 있고, 각 리뷰 시 해당 facet의 **문항 풀에서 최근 N회에 나오지 않은 variant**를 선택.
- **다양한 모드 결과 → FSRS 등급 변환 규칙** (모드 무관 공통 인터페이스):

| 결과 | 확신도 | 소요시간 | 힌트 | FSRS 등급 |
|---|---|---|---|---|
| 오답 / 점수 < 0.5 | any | any | any | 1 Again |
| 정답·점수 0.5~0.75 | any | any | 사용 | 2 Hard |
| 정답 | 낮음(≤50%) | any | 없음 | 2 Hard |
| 정답 | 보통~높음 | 중앙값 이내 | 없음 | 3 Good |
| 정답 | 매우 높음 | 개인 중앙값의 50% 이하 | 없음 | 4 Easy |

  (Jev `score`로 채점된 서술형은 기대점수 정규화 값으로 위 규칙 적용. 사용자에게는 "자동 추천 등급 + 1탭 수정" UI 제공 — 자기평가 편향 방지하면서 주도권 부여.)
- **목표 보존율 정책**(15년 장기 부하 관리의 핵심):
  - `core`(면접·실무 필수 기초: 자료구조, HTTP, SQL, OS 기초) = 0.92
  - `standard`(일반 섹션) = 0.90
  - `breadth`(주변 지식, L4~L5의 넓은 교양: 특정 도구 옵션, 역사적 배경) = 0.85
  - `archive`(S > 3년 && 최근 5회 연속 성공) = 0.80 + 자동 "유지 모드"
  - 근거: 보존율 0.9→0.95는 복습량을 대략 2배 이상으로 늘린다(위 간격 표: 0.40S). 15년간 KC가 수천~만 단위로 누적되므로 **계층별 보존율**이 필수.
- **일일 부하 관리**: 일일 리뷰 상한 + 신규 카드 상한, 연체 시 **R 오름차순(가장 잊혀가는 것부터)** 정렬, 1주 이상 공백 복귀 시 "복귀 모드"(연체량 N일 분산 재배치; 연체 카드는 FSRS가 R에 맞게 처리하므로 리셋 금지).
- **Leech(거머리 카드)**: lapses ≥ 6(권장) 또는 D ≥ 9 & 최근 4회 중 3회 실패 → 카드 정지가 아니라 **"개념 디깅(§3.5)"으로 에스컬레이션** + 카드 재작성 제안(카드가 나쁜 경우가 많음: 모호·복합 질문). 
- **개인 최적화 시점**: 리뷰 로그가 수백~1,000건 이상 누적된 후(재확인 필요) 월 1회 배치. 최적화 전후 log-loss 비교 후에만 교체(운영성, UR-17).

### 2.3 Interleaving (교차 연습)

- **메커니즘**: 서로 다른 유형을 섞으면 "어떤 전략을 쓸지 **판별(discrimination)**" 하는 연습이 추가되고, 연속 블록에서의 단기 기억 의존이 제거된다.
- **근거**: **B**. Rohrer & Taylor(2007) 수학 문제에서 지연 검사 큰 효과. Brunmair & Richter(2019) 메타분석 g ≈ 0.42, **유사하지만 헷갈리는 범주**에서 효과 크고, 단어 학습 등에서는 약하거나 역효과. 학습자는 교차 연습을 "덜 효과적"이라고 느낌(메타인지 착각).
- **적합**: K-P·K-S, L2 이상. 헷갈리는 쌍을 섞을 때 최대 효과: `process vs thread`, `Deployment vs StatefulSet`, `CSRF vs XSS`, `DP vs Greedy`, `RAG vs Fine-tuning`, `REST vs gRPC`, 정렬 알고리즘 선택.
- **UX**:
  - 신규 학습은 블록(blocked), 리뷰·연습은 교차 — 하이브리드("block then interleave").
  - "이 문제는 어떤 개념/알고리즘 유형인가?"를 먼저 묻는 **분류 선행 질문**(Jev `choice`로 채점 가능).
  - 섹션 간 교차 "믹스 세션" (예: 보안+백엔드: SQL injection ↔ ORM 파라미터 바인딩).
  - 사용자가 느끼는 어려움에 대한 **메타 설명 배너**: "섞어서 풀면 더 어렵게 느껴지지만 1주 후 성적이 더 좋습니다."

### 2.4 Generation Effect (생성 효과)

- **메커니즘**: 정보를 스스로 생성하면 읽기보다 부호화가 깊어진다(Slamecka & Graf 1978). Bertsch et al.(2007) 메타분석 d ≈ 0.40.
- **근거**: **A−**(단어 수준에서 강건, 복잡한 자료에서 조건부).
- **적합**: 전 유형. 코드에선 "빈칸 채우기 → 함수 전체 작성"으로 생성량을 레벨 따라 증가.
- **UX**: 해설 보기 전 "당신의 답/가설 먼저", 예시 생성 요구("이 개념이 적용되는 사례를 하나 들어보세요"), 코드 주석으로 설명 생성.

### 2.5 Desirable Difficulties (바람직한 어려움)

- **메커니즘**: Bjork(1994). 학습 중 수행을 낮추지만 장기 파지·전이를 높이는 조건들: 간격, 교차, 인출, 생성, 변동성(variability). **저장 강도(storage strength) vs 인출 강도(retrieval strength)** 구분 — 인출 강도가 낮을 때 성공하면 저장 강도가 크게 오름(FSRS의 `e^(w10(1−R))` 항과 동일한 원리).
- **근거**: **A**(구성요소별), 단 "바람직함"은 학습자가 성공할 수 있을 때만. 과도하면 undesirable.
- **UX**: 난이도 조절기(§8.2 flow channel)가 이 경계를 관리. 실패가 반복되면 즉시 scaffolding(힌트·worked example)로 전환.

### 2.6 OX(참/거짓) 퀴즈 — 사용자 요구(UR-14) 특화 분석

- **메커니즘**: 인출 형태이지만 재인(recognition) 중심이고 추측 확률 50% → 단독 사용 시 학습 효과·측정 신뢰도 모두 낮음.
- **근거**: **C**(단독), **B**(개선형: 거짓 진술을 교정하게 하는 T/F-with-correction, 확신도 결합).
- **개선 설계**:
  1. **오개념 기반 진술**: 거짓 진술은 실제 흔한 오개념에서 생성(예: "HTTPS면 XSS가 방지된다" X). → 오개념 라이브러리(`misconception` 엔티티)를 KC에 연결.
  2. **X 선택 시 "왜 틀렸나"를 한 줄 교정**하도록 요구(선택형 이유 또는 단답) → Jev `noul`로 교정 타당성 판정.
  3. **확신도 결합 CBM 채점**(§5.1)으로 추측 억제.
  4. 역할: 세션 **워밍업(3~5분)** 과 **빠른 진단(placement)** 용. 숙달 판정의 주 증거로는 사용하지 않음(가중치 낮춤).
- **UX**: 스와이프/키보드(←O, →X) 빠른 인터랙션, 10문항 1세트 60~90초, 결과 화면에 "확신했는데 틀린 것(고확신 오류)"을 강조 → 초과교정 효과(§5.1)로 연결.

## 3. 이해·정교화 계열

### 3.1 Elaborative Interrogation (정교화 질문)

- **메커니즘**: "왜 그런가?", "왜 X는 Y에서 성립하고 Z에선 아닌가?"에 답하며 새 정보를 기존 지식에 연결.
- **근거**: **B**(Dunlosky: moderate utility). Pressley et al.(1987) 등. **사전지식이 있을수록 효과 큼** → L1에는 약함.
- **적합**: K-C, K-S / L2~L5.
- **UX**: 개념 카드 뒷면에 "왜?" 프롬프트, 예) "왜 Kubernetes는 Pod를 최소 배포 단위로 하나?" → 자유 서술 → Jev `score`(4단계: 무관/사실 반복/인과 1개/인과+조건). LLM은 모범 답과 연결 개념 제시.

### 3.2 Self-Explanation (자기설명)

- **메커니즘**: 예제·코드의 각 단계를 스스로 설명하며 추론 공백을 메우고 정신 모델 수정(Chi et al. 1989, 1994).
- **근거**: **B+**. Bisra et al.(2018) 메타분석 g ≈ 0.55. 프롬프트가 구체적일수록 효과↑.
- **적합**: K-C, K-P(worked example과 결합 시 최강) / L1~L4.
- **UX**: Worked example 코드의 특정 라인에 "이 줄이 필요한 이유는?" 인라인 프롬프트. **서브골 라벨(subgoal labels)** 선택형 자기설명(“이 3줄은 어떤 하위목표? [입력 검증 / 상태 갱신 / 종료 조건]”) — CS 교육에서 효과 확인(Margulieux, Catrambone 등, 근거 B). 선택형은 결정적 채점, 서술형은 Jev.

### 3.3 Feynman Technique (파인만 기법) / Learning by Teaching

- **메커니즘**: ① 개념 선택 → ② 초보자에게 쉬운 말로 설명 → ③ 막히는 곳(공백) 발견 → ④ 원천으로 돌아가 보완 → ⑤ 단순화·비유. 학술적 근거는 "가르치기 위한 학습(learning by teaching)", **protégé effect**, 설명 생성: Fiorella & Mayer(2013, 2014) — 실제로 설명(녹화 강의)까지 할 때 지연 검사 향상. Nestojko et al.(2014) 가르칠 것을 기대만 해도 조직화 향상.
- **근거**: 기법 자체는 **D**(실무 유래), 구성 메커니즘은 **B**.
- **적합**: K-C, K-S / L3~L5(L5에서 특히 — 전문가의 "지식의 저주" 탐지).
- **UX (Interactive 모드)**: 
  - LLM이 **"헷갈리는 주니어" 페르소나**(예: "3개월차 신입 민수")로 질문 공세. 사용자의 설명에 대해 되묻기("그럼 캐시가 있으면 DB는 왜 필요해요?").
  - Jev 판정: `noul` "설명에 정의 없이 쓰인 전문용어가 있는가?", `score` "초보자가 이해할 수 있는 수준(0~3)", `noul` 각 핵심 idea unit 포함 여부, `choice` 비유의 적절성(적절/부분 오해 유발/오해 유발).
  - 결과: 공백 idea unit 리스트 → ④단계 "원천 복귀" 링크 → 해당 KC 카드 생성.

### 3.4 백지 복습법 (Blank-page Recall / Brain Dump / Free Recall)

한국 수험 문화에서 검증된 관행(“백지 복습”)이며 학술적으로는 **자유회상(free recall) 기반 인출 연습**이다. 단서가 최소(주제명만)여서 인출 난이도가 가장 높은 형태 → 효과가 크지만 좌절 위험도 큼.

- **메커니즘**: 단서 없는 인출 + 조직화(organization) 강제 → 구조적 지식 형성. Karpicke & Blunt(2011)에서 자유회상 형식 인출 연습이 개념맵 작성보다 우수. 비교(diff) 단계에서 메타인지 보정.
- **근거**: **A−**(자유회상 인출 연습), 채점·피드백 방식은 설계에 따라 다름.
- **적합**: K-C, K-F 묶음(한 단원), K-S(설계 리뷰 체크리스트 재현) / L2~L5. L1은 **부분 단서형(스캐폴딩)** 부터: 소제목 골격 제공 → 이후 골격 제거.
- **진행 절차 (UX)**:
  1. **Prompt**: 주제 + 범위만 제시("TCP 연결 수립과 종료 — 아는 것을 모두"). 타이머 5/10/15분(레벨별).
  2. **Write**: 마크다운 + 간단한 다이어그램(텍스트 기반 mermaid 혹은 박스·화살표 캔버스) 허용. 이 동안 자료 접근 차단(집중 모드 UI, 전체화면, 사이드바 숨김).
  3. **Self-mark(선택)**: 제출 전 "자신 있는 부분/애매한 부분" 하이라이트 → 보정 데이터.
  4. **Auto-score**: 아래 루브릭.
  5. **Diff view**: 기준 개념 그래프를 3색으로 — 회상함(초록)/누락(회색)/오류(빨강). 누락 핵심 항목은 클릭 시 해당 이론 섹션.
  6. **Remediate**: 누락·오류 idea unit → FSRS 카드 자동 생성/등급 Again 처리, 오개념 → OX 오개념 문항 연결.
  7. **Re-dump 예약**: 같은 주제 백지 복습을 1일 → 1주 → 1개월 확장 간격으로(단원 단위 FSRS 카드 1장으로 관리, facet=`free_recall`).

- **채점 모델 (Blank-page Score, BPS)**: 기준 자료 = 해당 주제의 **idea unit 목록**(명제 단위, 중요도 가중치 core=3/support=2/detail=1) + **관계 목록**(A→B 인과·포함·대조) + **오개념 목록**.

| 구성요소 | 가중치 | 측정 | 채점기 |
|---|---|---|---|
| Coverage (가중 회상률) | 0.45 | Σ(회상된 unit의 가중치)/Σ(전체 가중치) | Jev `noul` × unit별 ("노트가 `units.u_syn_ack`를 정확히 진술하는가?") |
| Accuracy (정확성) | 0.20 | 1 − (오류 진술 수 / 진술 수), 오개념 탐지 시 추가 감점 | Jev `noul` × 오개념별 + `choice`(정확/부분/오류) |
| Structure (관계·조직) | 0.20 | 관계 회상률 + SOLO 수준 | Jev `noul` × 관계별, Jev `score` SOLO 5단계 |
| Depth (깊이·확장) | 0.15 | 기준 외 **타당한** 확장(엣지 케이스, 실무 사례) | Jev `score`(0~3) + LLM이 "추가로 언급한 타당한 개념" 추출(→ UR-13 개념 가져오기 후보) |

  - 최종 `BPS = 100 × Σ(가중치 × 구성점수)`. FSRS 등급 매핑: BPS<50 Again / 50–69 Hard / 70–89 Good / ≥90 Easy.
  - **Jev 함정 회피**: idea unit을 배열이 아니라 **객체 키**(`units.u_syn_ack`)로 참조, 30개 초과 시 질문 분할(브리프 §3 명시 사항).
  - **오프라인/무AI 모드**: idea unit 체크리스트를 사용자에게 보여주고 자기채점 → 이후 동일 주제 AI 채점과의 차이로 **자기채점 편향**을 추적(메타인지 지표).
- **기준 idea unit 생성**: 콘텐츠 작성 시 LLM이 초안 생성 → Jev로 중복/모호성 필터 → 사람(사용자)이 1회 승인. 사용자가 반복적으로 "타당한 추가 개념"을 적으면 기준 목록에 편입 제안(개념 그래프 성장, UR-13).

### 3.5 Socratic Questioning / 개념 디깅 (Concept Digging, 5 Whys)

- **메커니즘**: 연쇄 질문으로 표면 지식 → 원리 → 전제 → 경계 조건까지 내려가며 오개념과 공백을 드러냄. 튜터링 연구(Graesser의 AutoTutor, 근거 B), 설명 기반 대화 튜터가 수동 읽기보다 우수(ICAP의 Interactive).
- **근거**: **B**(대화형 튜터링), "5 Whys" 자체는 **D**(Toyota 문제해결 관행).
- **적합**: K-C, K-S / L2~L5. L1에는 깊이 3단계로 제한.
- **디깅 래더 (Depth Ladder)** — 각 단계가 Bloom/SOLO 수준과 대응:

| 깊이 | 질문 유형 | 예 (주제: DB 인덱스) | 대응 수준 |
|---|---|---|---|
| D1 What | 정의 | 인덱스란? | Remember |
| D2 How | 작동 원리 | B+Tree로 어떻게 찾나? | Understand |
| D3 Why | 설계 이유 | 왜 B-Tree가 아니라 B+Tree? | Analyze |
| D4 Why-not / Trade-off | 대안·비용 | 인덱스를 많이 만들면 왜 안 되나? Hash index는 언제? | Evaluate |
| D5 When-it-breaks | 경계·실패 | 카디널리티 낮은 컬럼, 함수 적용 조건, 옵티마이저가 무시하는 경우 | Evaluate |
| D6 Connect | 타 개념 연결 | LSM-Tree(쓰기 최적화)와 비교, 캐시 지역성 | Relational |
| D7 Origin/Generalize | 역사·일반화 | 디스크 블록 I/O 비용 모델 → SSD/메모리 DB에서 가정은 유효한가? | Extended abstract |

- **엔진 설계 (LLM 생성 + Jev 판단 루프)**:
  1. LLM이 현재 깊이의 질문 생성(해당 KC 및 인접 KC 컨텍스트 주입).
  2. 사용자 응답.
  3. Jev `score`(0~3: 무응답/부정확/부분/충분) + `noul`(오개념 포함 여부) + `choice`(다음 행동: `deeper` / `same_level_rephrase` / `hint` / `teach_back` / `stop`).
  4. 3회 연속 D-level 실패 → 해설(LLM) + 해당 지점의 카드 생성 → 종료. 최대 깊이 도달 또는 12턴 상한.
  5. 세션 결과: "도달 깊이" 메트릭(KC별 최대 D) → **숙달 증거**와 **레벨 승급 증거**(L4 이상은 D4~D5 필요).
  6. 대화 중 새로 등장한 개념(예: "LSM-Tree") 중 개념 그래프에 없는 것 → **개념 가져오기 후보 큐**(UR-13).
- **UX**: 채팅형이지만 좌측에 "깊이 게이지(D1~D7)"와 "발견된 연결 개념" 미니 그래프를 실시간 표시 → 성취감 + 방향감. 사용자가 "모르겠다"를 눌러도 벌점 없음(심리적 안전).

### 3.6 Dual Coding (이중 부호화)

- **메커니즘**: 언어 + 시각 표상 두 채널로 부호화(Paivio 1971/1986). Mayer의 멀티미디어 원리(multimedia, contiguity, coherence, signaling, redundancy).
- **근거**: **B**(Mayer 원리들은 다수 실험에서 재현, 효과크기 원리별 상이). 단 Dunlosky의 "imagery for text"는 low utility — **학습자에게 그림을 상상하라고 하는 것**이 아닌 **정확한 도식 제공**이 핵심.
- **적합**: K-C(아키텍처, 네트워크 흐름, 자료구조 상태 변화) / L1~L3에서 크게, L4~L5는 학습자 스스로 도식 생성(Constructive).
- **UX**: 이론 페이지 = 좌 설명 / 우 다이어그램 인접 배치(공간 인접성), 스텝별 애니메이션(자료구조 시각화: 포인터 변화, K8s 스케줄링 흐름), 불필요 장식 배제(coherence). 다이어그램에 번호 → 본문 번호와 연결(signaling). **"다이어그램 재현" 문제**: 빈 박스·화살표를 드래그로 채우기 = 시각 인출.

### 3.7 Concept Mapping (개념맵)

- **메커니즘**: 개념 간 관계를 명시적으로 구성해 구조적 지식 형성.
- **근거**: **B−**. Nesbit & Adesope(2006) 메타분석에서 읽기·강의 대비 유의미한 효과. 그러나 Karpicke & Blunt(2011)에서 인출 연습보다 열위 → **"보면서 그리기"가 아니라 "기억에서 그리기(retrieval-based concept mapping)"** 로 설계.
- **적합**: K-C, K-S / L3~L5(섹션 간 연결: 보안↔인프라↔CI/CD).
- **UX**: 서비스의 **개념 그래프(KC graph)** 를 사용자 지식 맵으로 재사용. "빈 맵 퀴즈": 노드 일부만 주고 링크 라벨(“의존”, “대체”, “구현”) 채우기 → 결정적 채점 가능(정답 엣지 집합과 비교, 라벨은 Jev `choice`로 동의어 허용). 사용자의 개인 맵은 FSRS R로 색칠(“안개 걷힌 지도” — 모티베이션 §8).

### 3.8 Contrasting Cases (대조 사례) — 추가 권장

- **메커니즘**: 유사하지만 핵심 특징만 다른 사례를 나란히 비교해 결정적 특징 식별(Schwartz & Bransford 1998). 이후 설명을 들으면 학습 효과 큼("A Time for Telling").
- **근거**: **B**. **적합**: K-S, K-C / L3~L5.
- **UX**: 두 개의 Dockerfile / 두 개의 SQL 실행계획 / 두 개의 프롬프트 구조를 나란히 보여주고 "무엇이 다르고 어떤 결과 차이?" → Jev `choice`(핵심 차이 식별) + `score`(설명 품질).

## 4. 절차·기능 계열 (코드 중심)

### 4.1 Cognitive Load Theory (인지부하 이론) — 설계 제약

- **구성**: 내재적 부하(intrinsic, 요소 상호작용성) / 외재적 부하(extraneous, 나쁜 설계) / (본유적 germane, 최근 이론에서는 내재 부하에 흡수하는 추세). 작업기억 용량 제한(약 4±1 청크).
- **근거**: **A−**(Sweller 등 수십 년 실험; 일부 측정 방법론 비판 있음).
- **파생 효과와 서비스 적용**:

| 효과 | 내용 | UX/콘텐츠 규칙 |
|---|---|---|
| Worked example effect | 초보자는 풀이 예를 공부하는 것이 문제 풀기보다 효율적 | L1~L2 코드 단계는 worked example부터 |
| **Expertise reversal** (Kalyuga 2003) | 숙련자에게는 상세 안내가 오히려 부하 증가 | 레벨↑ → 스캐폴딩 자동 축소, "건너뛰기" 허용, L4+는 문제 먼저 |
| Split-attention | 서로 참조하는 정보가 떨어져 있으면 부하↑ | 코드 옆 인라인 주석, 다이어그램-설명 인접 |
| Redundancy | 같은 정보 중복 제시 시 부하↑ | 텍스트 그대로 읽는 음성·중복 요약 금지 |
| Element interactivity | 상호작용 요소 많은 내용은 분할 필요 | 한 화면 1 KC, 청크 단위 진행(스텝퍼) |
| Goal-free effect | 목표 없는 탐색이 초보자 부하 감소 | "이 코드에서 알아낼 수 있는 것 모두 적기" 문항 |
| Transient information | 영상/애니메이션은 사라지는 정보 | 애니메이션은 사용자 스텝 제어 가능해야 |

- **UI 함의**: 학습 모드는 **집중 모드 레이아웃**(네비·알림·게임 요소 숨김), 대시보드와 명확히 분리. 폰트·코드 가독성 우선.

### 4.2 Worked Examples → Faded Examples (풀이 예제 → 점진적 생략)

- **메커니즘**: 완전한 예제로 스키마 형성 → 단계적으로 풀이 단계를 제거해 학습자가 생성(Renkl & Atkinson 2003: **backward fading** — 마지막 단계부터 생략이 효과적).
- **근거**: **A−**(worked example), **B**(fading).
- **적합**: K-P / L1~L3.
- **코드 적용 사다리**: 
  1. 완전 예제 + 서브골 라벨 + 자기설명 프롬프트
  2. 마지막 서브골 빈칸(예: 이진탐색의 경계 갱신)
  3. 두 개 서브골 빈칸
  4. 함수 시그니처와 테스트만 주고 전체 구현
  5. 요구사항만 주고 설계+구현 (L3)
- 페이딩 진행은 **Elo 기반**: 해당 스킬 P(정답) ≥ 0.8이면 다음 단계, 연속 2회 실패면 이전 단계로.
- **채점**: 빈칸/전체 구현은 **테스트 케이스 실행(결정적)** — 로컬 샌드박스(Docker 또는 언어별 러너). 스타일/설계 품질은 Jev `score`(선택).

### 4.3 Parsons Problems (파슨스 문제)

- **메커니즘**: 뒤섞인 코드 라인을 올바른 순서(및 들여쓰기)로 배열. 구문 생성 부담 없이 **논리 구조**에 집중 → 인지부하↓.
- **근거**: **B**. Parsons & Haden(2006) 제안, Ericson et al.(2017): 동일 학습 성과를 코드 작성 대비 **더 짧은 시간**에 달성. Distractor(오답 라인) 포함 시 난이도↑, 짝지은 distractor(paired, 1줄 차이)가 오개념 진단에 유효.
- **적합**: K-P / L1~L2 (L3에선 복잡 로직·동시성 순서 문제, CI YAML 스텝 순서, K8s 매니페스트 조립 등으로 확장).
- **변형**: 1D(순서만), 2D(순서+들여쓰기, Python), distractor 포함, **적응형 Parsons**(실패 시 distractor 제거·라인 병합으로 쉬워짐 — Ericson 2018 계열).
- **채점**: 결정적 — 정답 순서와 비교(LIS/편집거리 기반 부분 점수) 또는 실행 기반(복수 정답 허용). AI 불필요.
- **UX**: 드래그&드롭 + 키보드(↑↓, Tab/Shift+Tab 들여쓰기), 실패 시 "첫 번째 잘못된 줄" 하이라이트.

### 4.4 PRIMM / 코드 추적(Predict–Run–Investigate–Modify–Make) — 추가 권장

- **메커니즘**: 실행 전 출력 **예측**(인출+정신 모델 검증) → 실행으로 즉시 피드백 → 탐구 → 수정 → 창작(Sentance et al. 2019, 근거 B). 코드 읽기 능력이 쓰기 능력의 선행조건(Lister et al.).
- **적합**: K-P, K-C(notional machine: 스코프, 클로저, 이벤트 루프 순서, 비동기 출력 순서) / L1~L3.
- **채점**: 결정적(출력 비교). "왜 그 출력인가" 설명은 Jev.

### 4.5 Deliberate Practice (의도적 연습)

- **메커니즘**: Ericsson et al.(1993) — ① 현재 능력 바로 위의 구체적 목표, ② 즉각적·정보적 피드백, ③ 반복과 정교화, ④ (코치가 설계한) 약점 집중.
- **근거**: **B−**. Macnamara et al.(2014) 메타분석: 수행 변량 설명력 — 게임 ~26%, 음악 ~21%, 스포츠 ~18%, 교육 ~4%, **전문직 <1%**. 즉 "1만 시간"은 과장, 그러나 **연습의 구조**는 여전히 유효. 전문직에서 효과가 작은 이유는 명확한 피드백 루프가 부족하기 때문 → 서비스가 그 루프를 만들어주는 것이 가치.
- **적합**: K-P, K-S / L2~L5.
- **UX**: **"약점 드릴(Weakness Drill)"** — 분석 엔진이 최근 오답 패턴(예: off-by-one, 비동기 에러 처리 누락, K8s probe 설정 혼동)을 클러스터링(Jev `choice`로 오답 원인 분류) → 해당 패턴만 5~10문항 집중 세트. 목표 명시("오늘 목표: 경계 조건 3종 정복"), 시간 측정, 전후 비교.

### 4.6 L4~L5 절차·판단 과제 (전문가 영역)

전문가 수준(UR-12)에서 카드·파슨스는 한계. 다음 과제형 학습을 **간격 반복 대상(“case card”)** 으로 편입:
- **장애 포스트모템 케이스**: 로그·메트릭 조각 제시 → 원인 가설 → 조치 우선순위. (K-S, Jev `score` 루브릭 + `choice` 원인 분류)
- **설계 리뷰**: 아키텍처 다이어그램/ADR 제시 → 리스크 3개 지적. (Jev `noul` × 기준 리스크별 + 추가 리스크 타당성 `score`)
- **코드 리뷰 드릴**: PR diff에서 버그·보안취약점·성능 문제 찾기. (심은 결함 목록과 대조 — 결정적 + Jev)
- **Productive Failure**(Kapur 2008, 근거 B): 설명 전 어려운 문제에 먼저 도전(예: 분산 락 설계) → 이후 정석(Redlock 논쟁, fencing token) 학습. L3~L5에서만.
- **트레이드오프 매트릭스 작성**: 선택지×기준 표 채우기 → 기준 가중치와 결론의 일관성 판정(Jev).

## 5. 메타인지 계열

### 5.1 Confidence-Based Marking (CBM) & Metacognitive Calibration

- **메커니즘**: 답과 함께 확신도를 표시하게 하면 ① 추측과 지식을 구분, ② 자기 모니터링 훈련, ③ **초과교정 효과(hypercorrection effect)** — 높은 확신으로 틀린 오류는 교정 후 더 잘 기억됨(Butterfield & Metcalfe 2001, 근거 B+). 
- **근거**: CBM 채점체계 Gardner-Medwin(1995~, 의학교육, 근거 B). 보정 훈련 자체의 전이 효과는 **C~B**.
- **Gardner-Medwin CBM 점수표** (권장 채택):

| 확신도 | 정답 | 오답 |
|---|---|---|
| C1 (낮음, ~<67%) | +1 | 0 |
| C2 (중간, 67–80%) | +2 | −2 |
| C3 (높음, >80%) | +3 | −6 |

  → 기대점수 최대화가 곧 정직한 확신도 보고(proper scoring rule 성질).
- **보정 지표 (운영 대시보드)**:
  - **Brier score** = mean((p − y)²), p = 확신도 확률(예: C1=0.55, C2=0.75, C3=0.92).
  - **Calibration curve**(확신도 구간별 실제 정답률)와 **ECE**(expected calibration error).
  - **과신 지수** = mean(p) − mean(y). 섹션별로 표시("보안 섹션에서 과신 +18%p").
- **스케줄링 연계**: 고확신 오류 → FSRS Again + **24시간 내 재출제** + 개념 디깅 제안. 저확신 정답 → Hard(과소평가된 지식 강화).
- **UX**: 답 제출 버튼을 3개로 분리 **[애매해요] [아마도] [확실해요]** — 추가 클릭 없이 확신도 수집(마찰 최소). 주간 리포트에 보정 곡선.

### 5.2 Self-assessment 편향 관리

- 자기채점(self-grade)은 편리하지만 관대화 경향(Dunning–Kruger류 편향, 해석 논쟁 있음). 대책: 자기채점과 자동채점이 모두 가능한 문항에서 **차이를 지속 측정** → 편향이 큰 섹션은 자기채점 옵션을 줄이고 자동 채점 강제.

## 6. 분류 체계 (문제 생성·레벨링의 좌표계)

### 6.1 Bloom's Revised Taxonomy (Anderson & Krathwohl 2001) — 출제 2차원 매트릭스

인지과정 6단계(Remember, Understand, Apply, Analyze, Evaluate, Create) × 지식 4차원(Factual, Conceptual, Procedural, Metacognitive).

| | Remember | Understand | Apply | Analyze | Evaluate | Create |
|---|---|---|---|---|---|---|
| **Factual** | OX, 용어 cloze | 예시 판별 | — | — | — | — |
| **Conceptual** | 정의 인출 | 비유·설명, 분류 | 개념을 새 상황에 적용 | 대조 사례, 원인 분석 | 트레이드오프 판단 | 새 모델/비유 설계 |
| **Procedural** | 명령·절차 순서 | 코드 추적(PRIMM) | 구현, faded example | 디버깅, 성능 분석 | 코드 리뷰, 대안 비교 | 시스템·파이프라인 설계 |
| **Metacognitive** | — | 확신도 표시 | 학습 전략 선택 | 오답 패턴 분석 | 자기 평가 보정 | 개인 학습 계획 수립 |

- **문제 생성 로직(UR-13)에 주는 요구**: 모든 문항은 메타데이터 `(kc_id, bloom_process, knowledge_type, level L1–L5, format, misconception_ids[], difficulty_β)`를 가진다. LLM에게 "KC X에 대해 Analyze×Procedural, L3, 디버깅 형식"처럼 **좌표 지정 생성**을 요청 → Jev `choice`로 **생성된 문항의 실제 Bloom 수준을 재분류**해 불일치 시 폐기/재생성 (생성-판정 분리 품질 게이트).
- **품질 게이트(Jev)**: `noul` "정답이 유일한가", `noul` "지문만으로 풀 수 있는가(answerability)", `noul` "정답 누설(단서) 존재", `score` "오답 선택지의 그럴듯함(0~3)", `choice` 실제 Bloom 수준, `noul` "사실 오류 가능성" → 불통과 문항은 풀에 넣지 않음.

### 6.2 SOLO Taxonomy (Biggs & Collis 1982) — 서술형·백지노트 채점 루브릭

| SOLO | 기술 | 개발 예 (주제: 캐시) | 레벨 대응 |
|---|---|---|---|
| Prestructural | 무관하거나 오해 | "캐시는 저장소다" 수준의 무의미 진술 | — |
| Unistructural | 관련 요소 1개 | "캐시는 빠르다" | L1 |
| Multistructural | 여러 요소 나열, 연결 없음 | TTL, LRU, 캐시 히트 나열 | L1~L2 |
| Relational | 요소들이 전체로 통합, 인과 설명 | 워크로드 특성에 따라 eviction과 TTL을 선택하고 일관성과의 트레이드오프 설명 | L3~L4 |
| Extended abstract | 원리를 일반화·새 맥락 전이 | 캐시 일관성을 분산 시스템 일반의 stale-read 문제로 일반화, CDN·CPU 캐시·LLM 프롬프트 캐시까지 연결 | L4~L5 |

- **Jev 구현**: `score(instructions, [prestructural 기술, uni, multi, relational, extended])` → 기대점수(0~4)와 confidence. confidence 낮으면 LLM-judge 2차 검토 또는 사용자에게 "채점 확신 낮음" 표시.

### 6.3 Dreyfus 모델 — 레벨별 지원 방식

- Novice: 맥락 없는 규칙 → **체크리스트·규칙 카드**. Advanced beginner: 상황 요소 → **사례 기반 예제**. Competent: 계획·선택 → **의사결정 문제**. Proficient: 전체 조망 → **패턴 인식 드릴(짧은 시간에 이상 탐지)**. Expert: 직관 → **경계·반례 탐구, 가르치기, 표준 작성**.
- 레벨은 **자기선언 + 배치 진단(placement)** 으로 시작해, 증거로 자동 조정(§7.3).

## 7. 숙달·지식 추적 (Knowledge Tracing)

### 7.1 Mastery Learning (Bloom 1968, 1984)

- **메커니즘**: 선수 단위 숙달(기준 예: 80~90%) 후 진행, 미달 시 교정 학습 후 재평가. Bloom(1984) "2 Sigma problem"(1:1 튜터링 + 숙달학습).
- **근거**: **A−**. Kulik, Kulik & Bangert-Drowns(1990) 메타분석 ES ≈ 0.52. (2 sigma 수치 자체는 재현 시 더 작다는 비판 존재.)
- **서비스 기준(권장)**:
  - KC 숙달(Mastered): Elo P(정답 | 해당 레벨 중앙 난이도 문항) ≥ 0.80 **그리고** 서로 다른 형식 ≥ 3종에서 증거 **그리고** 최소 2개의 서로 다른 날짜(간격 증거).
  - BKT 사용 시 P(L) ≥ 0.95 (Cognitive Tutor 관행).
  - 유지(Retained): FSRS R ≥ 목표 보존율(현재 시점).
  - **"숙달 ≠ 유지"를 UI에서 분리 표시**: 숙달했지만 R이 떨어진 KC = "녹슨 스킬" 배지 → 리뷰 유도.
- 선수 관계(prerequisite graph)는 KC 그래프의 엣지 `requires`. 하위 KC 미숙달 시 상위 KC 신규 학습 **권고 차단(soft gate)** — 하드 차단은 15년차 사용자의 자율성 침해(SDT)이므로 경고만.

### 7.2 모델 비교: BKT vs Elo vs IRT

| 모델 | 핵심 | 파라미터 | 장점 | 단점 | 서비스 역할 |
|---|---|---|---|---|---|
| **BKT** (Corbett & Anderson 1995) | KC별 숨은 이진상태(학습됨/아님)의 HMM | P(L0), P(T) 학습률, P(G) 추측, P(S) 실수 | 해석 쉬움, 숙달 판정 명확 | KC별 파라미터 적합 필요, 망각 미포함, 문항 난이도 무시 | 선택(L1~L2 절차 스킬 숙달 판정) |
| **Elo** (Pelánek 2016 교육 적용) | 학습자 능력 θ, 문항 난이도 β, 온라인 갱신 | K(불확실도 함수) | 단일 사용자·콜드스타트에 강함, 문항 난이도 자동 보정, 계산 O(1) | 학습(성장) 반영이 K에 의존 | **주력**: 적응형 출제·난이도 추정 |
| **IRT 1PL/2PL** | P = σ(a(θ − b)) | b 난이도, a 변별도 (+c 추측 3PL) | 심리측정 표준, 배치 진단에 최적 | 대규모 응답 데이터 필요 → 단일 사용자는 추정 불가 | 문항 초기 난이도의 **사전분포**(LLM 추정 b 사용), 배치 진단 CAT |

- **BKT 갱신식**:
  - 정답 관측: `P(L|correct) = P(L)(1−S) / [P(L)(1−S) + (1−P(L))G]`
  - 오답 관측: `P(L|wrong) = P(L)S / [P(L)S + (1−P(L))(1−G)]`
  - 전이: `P(L_next) = P(L|obs) + (1 − P(L|obs))·T`
  - 기본값 예: P(L0)=0.1~0.3, T=0.1~0.2, G=0.2(4지선다 0.25, OX 0.5!), S=0.1. **형식별 G를 다르게** 두는 것이 핵심(OX는 증거가 약함).
- **Elo 갱신식 (권장 구현)**:
  - `P = 1 / (1 + e^(−(θ_{u,kc} − β_item)))`
  - `θ ← θ + K_u · (y − P)`, `β ← β − K_i · (y − P)`
  - `K(n) = α / (1 + b·n)` (n = 해당 대상의 관측 수; 예 α=0.8, b=0.05) → 초기 빠르게 수렴, 이후 안정.
  - y는 이진 또는 부분점수(0~1; Jev score 정규화)도 허용.
  - θ는 **계층형**: 글로벌 θ_u → 섹션 θ_{u,section} → KC θ_{u,kc} (관측 적은 KC는 상위 θ로 shrinkage). 15년 장기 사용에서 신규 KC 콜드스타트 해결.
  - 단일 사용자 환경에서 β(문항 난이도)는 한 사람의 데이터로만 보정되므로 **LLM이 생성 시 추정한 난이도(1~5) → β 초기값**, 이후 Elo로 미세 조정.
- **학습-망각 통합**: 숙달(Elo θ)과 유지(FSRS R)를 합성한 "현재 실력 추정" = `θ_eff = θ_kc + λ·log(R/0.9)` 등 단순 결합은 연구 근거가 약하므로(**C**), **v1은 두 지표를 분리 표시**하고 결합은 추후 데이터로 검증.

### 7.3 레벨 승급 규칙 (섹션 단위)

- 섹션 S의 레벨 Lk → Lk+1 조건(권장, 조정 가능):
  1. 해당 섹션 Lk 필수 KC의 **≥ 85% Mastered**, 
  2. Lk+1 대표 문항 세트(“승급 평가”, 10~15문항, 형식 혼합, Bloom 상위 과정 포함)에서 CBM 기준 ≥ 70%,
  3. L3+ 승급은 **개념 디깅 D4 이상 도달 ≥ 5개 KC**, L4+ 승급은 **케이스 과제(설계 리뷰/포스트모템) 루브릭 평균 ≥ 2.5/4**.
- 강등은 없음(동기 저하). 대신 R 하락 시 "녹슨 KC" 표시.

## 8. 동기·몰입·질림 방지 (UR-14 "질리지 않게")

### 8.1 이론적 기반

- **자기결정이론(SDT, Deci & Ryan)**: 자율성(autonomy)·유능감(competence)·관계성(relatedness)이 내재동기를 지탱. 로컬 단일 사용자 → 관계성은 "AI 튜터 페르소나", "과거의 나와 비교"로 보완.
- **과잉정당화 효과(Overjustification)**: Deci, Koestner & Ryan(1999) 메타분석 — **기대된·과제 수행 조건부 외적 보상은 내재동기를 저하**(근거 A−). → 포인트/코인 "보상"을 학습 활동의 목적처럼 보이게 하면 안 됨.
- **Flow(Csikszentmihalyi)**: 도전 수준 ≈ 기술 수준일 때 몰입. 지루함(쉬움) ↔ 불안(어려움) 사이 채널.

### 8.2 Flow Channel 운영 = 적응형 난이도 제어

- 목표 성공률 **70~85%** 대역: 교육 연구의 경험적 권고(ZPD 운영 관행) + Wilson et al.(2019)의 "85% 규칙"(이진 분류 학습자의 이론적 최적 오류율 ≈ 15.9%; 인간 교육 전이는 **C**, 경험칙으로만 사용).
- 구현: Elo로 각 후보 문항의 P(정답) 예측 → **목표 P ∈ [0.70, 0.85]** 인 문항 우선. 모드별 조정: 리뷰(카드)는 FSRS가 결정(보존율 0.9 ≈ 성공률 90%), 신규 연습은 0.75, "보스 챌린지"는 0.5.
- **실패 연속 보호**: 연속 3오답 → 난이도 1단계 하향 + 격려형 쉬운 문제 1개("momentum item"). 연속 8정답 → 난이도 상향 제안.

### 8.3 Novelty Rotation (신선도 로테이션)

- 모드 풀: OX / 카드 인출 / cloze / 코드 예측 / Parsons / faded 구현 / 디버깅 / 백지노트 / 개념 디깅 / 개념맵 / 대조 사례 / Feynman / 케이스 과제.
- **로테이션 규칙**: 동일 모드 연속 ≤ 2블록, 세션당 최소 3종 모드, 최근 7일 사용 빈도 낮은 모드 가중치↑(탐험 보너스), 사용자 선호 모드 가중치(자율성) — **softmax(선호 + 교육효용 + 신선도 − 피로)**.
- **주간 테마 / 이벤트**: "보안 주간", "장애 대응 챌린지", "고전 논문 주간(Raft, MapReduce, Attention Is All You Need)". 섹션 순환으로 15년 사용의 권태 방지.
- **변동 도전(Variable challenge)**: 세션마다 1회 "보스 문제"(상위 레벨 문항, 실패 부담 없음·보너스 경험) — 예측 가능한 루틴 + 약간의 불확실성. 단, 가변 보상(variable-ratio 도박형 루트박스)은 금지.

### 8.4 번아웃 없는 스트릭 설계

| 안티패턴 | 문제 | 대안 |
|---|---|---|
| 일간 스트릭 + 끊기면 0 | 손실회피 압박, 끊긴 후 이탈 | **주간 목표 스트릭**(예: 주 4일 학습 달성 = 1주 연속) |
| 매일 동일 분량 강요 | 바쁜 날 포기 → 이탈 | **최소 유효 학습일(MVD)**: 5분/리뷰 10개 = 인정 |
| 휴식 불허 | 번아웃 | **휴식 토큰**(주 1~2회 자동), 여행/시험 "일시정지 모드"(FSRS 연체는 R 기반으로 자연 처리) |
| 스트릭 자체가 목표 | 굿하트 법칙(쉬운 것만 풀기) | 스트릭 인정 조건에 "리뷰 due의 일정 비율" 포함, 스트릭보다 **역량 지표**를 메인에 |
| 과부하 스트릭 | 연체 폭증 → 좌절 | 일일 상한 + "오늘은 여기까지" 종료 권고(세션 45분 이상 시 휴식 권장) |

- (Duolingo 등 상용 서비스는 streak freeze 도입으로 이탈 감소를 공개적으로 보고해 왔다 — 산업 근거 **D**.)

### 8.5 게이미피케이션 함정

- **근거**: Sailer & Homner(2020) 메타분석 — 인지적 학습 결과 g ≈ 0.49, 동기 0.36, 행동 0.25 수준이나 연구 이질성 크고, 설계 요소에 따라 편차. Hanus & Fox(2015): 배지·리더보드 적용 수업에서 오히려 내재동기·만족도·시험 점수 하락(**B**).
- **금지/주의 목록**:
  1. **리더보드** — 로컬 단일 사용자에게 무의미, 비교 대상은 "과거의 나"(성장 곡선)만.
  2. **포인트 인플레이션** — XP가 학습량이 아닌 "클릭 수"를 보상하면 저품질 행동(쉬운 OX 반복) 유발. XP를 쓰더라도 **교육적 효용 가중치**(난이도·모드·보정 정확도)로 산출하고, 메인 KPI로 쓰지 않음.
  3. **시스템 게이밍** — 빠른 추측·힌트 남용(Baker et al.의 gaming-the-system). 탐지: 응답시간 < 개인 하위 5% & 오답, 힌트 즉시 요청 반복 → 해당 세션 증거 가중치 하향, 부드러운 안내.
  4. **무의미 배지** — "첫 로그인" 류 금지. 배지는 **역량 이정표**(예: "TCP 핸드셰이크 D5 도달", "보안 섹션 L3")로만.
  5. **외적 보상의 조건부화** — "문제 10개 풀면 코인" 대신 **정보적 피드백**("경계 조건 오류율 32% → 11%").
- **권장 동기 장치(역량 가시화)**: 섹션 레이더 차트(L1~L5), **지식 지도 안개(fog-of-war)** — KC 그래프를 FSRS R/숙달도로 채색, 15년 로드맵 상의 현재 위치, 월간 "성장 리포트"(새로 숙달한 KC, 보정 개선, 최장 인출 간격 달성).

## 9. AI/Jev 채점 아키텍처 입력 (UR-15, UR-16)

### 9.1 채점 사다리 (Grading Ladder)

| 순위 | 채점기 | 대상 | 비용/지연 | 신뢰도 |
|---|---|---|---|---|
| 1 | **Deterministic** | OX, MCQ, Parsons, 출력 예측, 테스트 기반 코드, 개념맵 엣지 | 0 / ms | 최고 |
| 2 | **Jev** (`noul`/`choice`/`score`) | 서술형 루브릭, idea unit 포함 여부, 오개념 탐지, SOLO 수준, 다음 행동 라우팅, 문항 품질 게이트, 오답 원인 분류 | 매우 저렴 / ~250ms | 높음(판단형), confidence 제공 |
| 3 | **LLM-as-judge** (claude -p / codex exec / API / Ollama) | 해설이 필요한 피드백, 모범답안 대비 차이 설명, 복합 설계 과제 서술 피드백 | 비쌈 / 수 초 | 중간(편향·변동) |
| 4 | **Self-grade** | 오프라인·AI 비활성 시, 사용자 선택 | 0 | 편향 → 추적 보정 |

- 원칙: **LLM = 생성(문제·해설·소크라테스 질문·페르소나)**, **Jev = 판단(채점·분류·라우팅·필터)**. Jev 결과의 `confidence`가 임계(예: 0.6) 미만이면 사다리를 한 단계 올려 LLM-judge 재검토 또는 사용자 확인.
- **Jev 상태(state) 설계 규칙**: 참조 대상은 **객체 키**(`rubric.r_def`, `units.u_syn_ack`, `misconceptions.m_https_xss`)로, 대량 항목은 질문 분할. 동일 요청 7일 캐시 → 같은 답안 재채점 비용 0(재현성에 유리).
- **AI 부재 시 우아한 저하(graceful degradation)**: 모든 모드는 결정적 채점 또는 자기채점 대체 경로를 가진다(로컬 우선, UR-15/17).

### 9.2 모드별 Jev 질문 템플릿(요지)

| 모드 | Jev 질문 |
|---|---|
| 백지노트 | `noul` per idea unit / per relation / per misconception; `score` SOLO 5단계 |
| 개념 디깅 | `score` 답변 충분성 0–3; `noul` 오개념 포함; `choice` next ∈ {deeper, rephrase, hint, teach_back, stop} |
| Feynman | `noul` 미정의 전문용어 사용; `score` 초보자 이해가능성 0–3; `choice` 비유 적절성 |
| 자기설명/정교화 | `score` 4단계(무관/반복/인과1/인과+조건) |
| OX 교정 | `noul` 교정 문장이 오류를 바르게 고쳤는가 |
| 오답 분석 | `choice` 오류 원인 ∈ {개념 오해, 절차 실수, 부주의, 문제 오독, 선수지식 부족} → 약점 드릴 입력 |
| 문항 품질 게이트 | `noul` 유일 정답/answerability/단서 누설/사실오류 의심; `choice` Bloom 수준; `score` 오답지 그럴듯함 |
| 케이스 과제 | `noul` per 기준 리스크; `score` 루브릭 차원별(정확성·우선순위·트레이드오프·커뮤니케이션) |

## 11. 15년 장기 운영에 대한 시사점 (UR-12, UR-17)

1. **카드 폭증 관리**: 5년 후 KC 수천, 카드 만 단위 가능. → 계층별 desired retention(§2.2.3), `archive` 유지모드, FSRS 워크로드 시뮬레이터로 "보존율 변경 시 일일 리뷰량 예측" UI 제공.
2. **지식의 노후화(Knowledge decay ≠ 망각)**: 기술은 바뀐다(예: Docker Compose v1→v2, K8s dockershim 제거). KC에 `valid_as_of`, `deprecated_by` 메타데이터와 "개념 갱신 알림" 필요 → R1이 아닌 콘텐츠/데이터 수집 설계(R-데이터)로 이관.
3. **레벨 전환 시 방법 전환**: Expertise reversal 때문에 같은 UI를 15년 쓰면 효과가 떨어진다. 섹션 레벨에 따라 **기본 모드 믹스가 자동 전환**되어야 함(§10.2).
4. **증거 로그의 영속성**: review_log·attempt_log는 불변 이벤트로 보존 → 향후 FSRS 재최적화, Elo 재계산, 모델 교체(예: 향후 FSRS-7) 시 **리플레이** 가능해야 함(운영성).
5. **동기 곡선**: 초기(0~1년)는 빠른 성장 가시화, 중기(3~6년)는 섹션 확장·깊이 게이지, 장기(10년+)는 "가르치기·표준 작성(Create)"과 개인 지식 베이스 기여로 동기 원천 이동.

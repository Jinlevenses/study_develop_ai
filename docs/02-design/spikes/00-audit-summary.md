## SP-2 — PASS

### 불일치·과대주장 (Discrepancies)
- The '52/52 PASS' count includes RES-14 (result forgery), which is never blocked: the harness records any accepted-risk item as pass=true. The accurate breakdown is 37 isolation attacks with 0 full-layer escapes, 14 resource-containment tests all ending in the expected status, and 1 accepted risk that is not mitigated. Criterion 1 (>= 20 attempts, all fail) is still met.
- Section 3 item 5 says escapes are judged by host-side effects, 'not child stdout'. In fact hostEffects() also counts the payload's own printed ESCAPED: marker as an escape. For 20 of the 37 control rows (FS-03, FS-06..08, PR-01..05, PR-07, NET-07, NET-09, NET-10, MOD-01..07, ENV-01), the none-layer positive control rests only on that self-reported marker; no host-side effect was observed. Their full-layer 'blocked' verdicts rest on the marker being absent plus error codes the payload caught itself. Every full-layer row did print the expected number of specific error codes, so no pass came from a child that simply failed to run.
- The report calls the catalogue 'JS/TS 52건', but every attack runs as lang js (MOD-04 as cjs). None runs through the TS entry (.mts with type stripping in the child); TS was measured for latency only.
- The watchdog overshoot is understated: at the 100ms interval the re-run peaked at 394.3MB against the reported 381MB (about 1.54x the 256MB limit). At 50ms it peaked at 354.6MB against the reported 347MB. These are sampled values, not an upper bound.
- In the netns-only experiment (P6), the report lists only NET-01/03/04/06 as blocked. The same run shows NET-07 (localhost DNS lookup) and NET-10 (listening on loopback inside the namespace) succeeding. Neither reached the host (0 hits), but the report leaves them out.
- Latency numbers were not reproduced exactly: the re-run was faster (JS typical p95 62.8ms, TS 155.1ms, SQL 74.2ms, 4 concurrent 65.0ms). The PASS against the 1.5s target holds.
- Only 5 of the 16 SQL attacks have a no-tokenizer control (the file-creating ones: SQL-01..04 and SQL-07; SQL-04's control created no file). The other rejections show only that the tokenizer refused them.
- Scope limits the report already states: Linux and uid 0 only; the prewarmed-spare path was not run through the attack suite; Windows and macOS were not run.

### 구속 결정 (Binding decisions)
- The runner is one dedicated child process per request, never a reusable worker pool. The only exception is a single-use prewarmed spare, and it may be adopted only after the full attack suite passes on the spare path.
- Child flags: --permission; fs read limited to the guard file and the per-request tmp dir; fs write denied by default; no --allow-child-process, --allow-worker, --allow-addons or --allow-wasi; --disallow-code-generation-from-strings; --max-old-space-size=128; --no-addons; --disable-wasm-trap-handler (required with RLIMIT_AS on Linux); an empty env; detached process group with a group SIGKILL.
- A preload guard is mandatory. It uses a default-deny builtin allowlist enforced in module.registerHooks on the resolved node: URL, wraps process.getBuiltinModule, and denies sqlite in JS mode plus vm, v8, os, module, wasi, tty, cluster and repl. It also stubs fetch, WebSocket and EventSource; disables net.Socket.prototype.connect and Server.listen; allows process.kill on its own pid only; blocks execve, _debugProcess, binding, dlopen, setuid* and report; and locks every guard property non-writable and non-configurable.
- Network isolation is JS-level only, not kernel-level (RSK-RUN-02). The 127.0.0.1 service API must still require its internal token. An optional netns (Linux) or Docker --network none path is kept as hardening.
- The SQL tokenizer is the only gate against ATTACH and VACUUM INTO (node:sqlite has no authorizer). The design requires full lexing with a statement allowlist, checked in both parent and child, plus :memory:, allowExtension:false, max_page_count and a 1000-row / 1KB-cell cap. hard_heap_limit must not be relied on.
- Memory is enforced by the RSS watchdog, sampling every 25-50ms (100ms overshoots to about 400MB), plus RLIMIT_AS 1.5GB, RLIMIT_CPU and RLIMIT_FSIZE on Linux. RLIMIT_NPROC must not be used. The stdout/stderr cap is judged with >= 64KB.
- Graders must never trust learner stdout (RES-14, result forgery). Hidden-test results must come through a separate channel or a separate process.
- TypeScript is stripped in the parent with module.stripTypeScriptTypes and run as .mjs, so the JS attack suite covers the TS path. Running .mts directly in the child is not verified.
- The attack suite, with host-observable controls, becomes a V-ci regression gate. The Node minor version is pinned.
- Windows and macOS runners are unverified (V-live pending). Each needs a platform-specific tree kill (Job Object or taskkill), RSS polling and env bootstrap, and must re-run the suite before task formats that need the runner are enabled on that OS. The pre-agreed fallback applies: disable the task format and recommend Docker.

## SP-3 — PARTIAL

### 불일치·과대주장 (Discrepancies)
- Re-ran the full `npm run spike` in a scratchpad copy; the original results.json was not touched. Every deterministic output matched the report exactly: projection 5d6dd51c...8888, chain head 108a861d, merge 494f1cc2...8345, three-way 576d8ef4, the forecast tables, and LDI relDiff 6.1e-16. The only exception is the fuzz 'random' negative control, which uses Math.random by design: 3,121/3,380 cards mismatched vs the reported 3,040/3,316 (still 92%). So the report's claim that all hashes were identical across runs does not cover this control. Timings were faster than reported (gen 11.4s, replay 7.5s), except FULL-sync p99, which was 11.7ms vs the reported 8.0ms. All timings are still far under the thresholds.
- Append-only overclaim: the spike only tested UPDATE and DELETE. The auditor found that INSERT OR REPLACE and REPLACE INTO silently overwrite or delete ledger rows without triggering the guard, because recursive_triggers is OFF by default. DROP TRIGGER is also allowed. With PRAGMA recursive_triggers=ON, REPLACE is rejected.
- Hash chain tamper detection was never negatively tested. In the auditor's test, tampering a middle row was detected (1 broken link), but tampering a device's last row was NOT detected (0 broken links), because the chain head is not anchored anywhere.
- The fuzz 'embedded' test could not tell an embedded seed apart from the library's default seed, since both are deterministic. The auditor's extra check closes this gap: replaying the embedded ledger while ignoring the stored seed gave 3,066/3,307 card mismatches, which shows the embedded seed is actually used.
- The forecast accuracy is circular: the synthetic learner's ground truth is built from the same FSRS forgetting_curve(default_w, S) that the 'model' forecaster uses. So the 3.9% median error and the choice of model over observed are optimistic, sim-only results. The '14/14 windows with >=20 active days' figure groups windows by activity in the future forecast window, which cannot be known when forecasting. How often the ±15% band contains the actual value was not tested: it did for 15/16 main, 9/10 alt1 and only 5/10 alt2 windows.
- The LDI incremental 'term cache' check was done at one fixed evaluation time. Because R_k(t) depends on t, the cached terms become invalid when the display time changes. The honest conclusion is that a full recompute (9-14ms) is enough.
- LDI parameter sensitivity is in the convergence doc's SP-3 method column, and §4.7 line 401 and DEC-CNV-03 rely on it, but it was not performed. Only a stand-in LDI was used, so ldi_params@v1 is still unconfirmed.
- The LiveLedger correction path, both append(correction) and importRows with corrections, ran 0 times. The report's '정정도 slow path' (corrections take the slow path) is a design claim, not a measurement.
- Merge order invariance holds by construction, because the replay sorts by a total key. The real evidence is dedupe, incremental merge equal to full rebuild, and the negative controls. The PASS stands.
- The mastery rule's 'distinct days' is computed as UTC days (floor(ts/86400000)), which puts the day boundary at 09:00 KST instead of FR-PRG-027's 04:00 boundary.
- Replay depends on constants that are not in the ledger: FSRS weights, retention, short-term setting, fuzz, Elo K. payload.policy_version is never read during replay.

### 구속 결정 (Binding decisions)
- Event envelope is (id ULID, device_id ULID ASCII with CHECK pattern, device_seq, client_ts ms, type, payload JSON with STORED card_id and concept_id). UNIQUE(device_id, device_seq). Replay total order is ORDER BY client_ts, device_id, device_seq; never replay by rowid or arrival order.
- Per-device client_ts must be monotonic: ts = max(wall_now, last_ts_of_device + 1). Apply events to a card only in non-decreasing ts order. If ts-fsrs throws FSRSValidationError, raise it as a ledger-integrity alarm and do not swallow it.
- Ledger inserts must be INSERT OR IGNORE only, which makes import idempotent. Forbid INSERT OR REPLACE, REPLACE and ON CONFLICT DO UPDATE on events (enforce with a static check). Set PRAGMA recursive_triggers=ON on every ledger connection. Treat the triggers as protection against mistakes, not as a security boundary.
- Anchor each device's hash-chain head (device_id, device_seq, head_hash) outside the ledger, in the checkpoint manifest and the sync exchange, so that tail tampering and truncation are detectable.
- The authoritative projection is a pure reducer over payload + client_ts. It must not read the clock, random numbers, settings or content/assessment DBs. The payload must embed every replay input: card_id, concept_id, facet, format, tier, rating, result, w_format, w_grader, gaming_factor, rapid, item_beta snapshot, policy_version, prev_hash, fuzz_seed if fuzz is on, and fsrs_at/study_day.
- FSRS: pin ts-fsrs to exactly 5.4.2 and use f.next(card, ts, grade). Persist numeric ms only, never Date objects. The authoritative projection uses enable_fuzz=false; any spreading of reviews is non-persistent jitter at queue assembly. If fuzz is ever enabled, a fuzz_seed in the payload is mandatory (schema-enforced); fuzz with an unstored seed is forbidden.
- Put projection parameters (FSRS w, retention per tier, short-term, fuzz, Elo K, mastery thresholds) in versioned, immutable parameter sets that events reference, e.g. by policy_version/fsrs_params_version. Replay selects parameters from the event, never from current config. Upgrades run as full rebuild + projection-hash diff migrations, with the fsrs_impl version stored alongside the hash.
- Day-boundary logic (FSRS input time and mastery's distinct-days rule) must use a study_day/fsrs_at fixed at event creation and stored in the payload. Replay must never recompute it from the process TZ or current settings.
- A canonical projection hash (sorted keys, fixed field order, shortest round-trip numbers, SHA-256) is recorded in checkpoint manifests and used for merge/upgrade regression checks and nightly integrity checks. Byte equality is required only within the same platform and Node version; cross-OS comparison is deferred to V-live.
- Incremental path: take the fast path only when the card's last_review < ts and the concept's last_ts < ts (strict). Otherwise re-derive the card or concept key through ix_card/ix_concept. Corrections use a two-pass void set. After a bulk merge, rebuild the projection with a background full replay (about 10s for 550k events) and atomically swap the projection tables.
- LDI is fully recomputed at display time (about 10ms). Do not cache time-dependent terms. A separate LDI snapshot table is not needed; keep only the schema hook.
- The load forecast is shown only as a range, never as daily values. The band width is calibrated from each user's historical forecast error rather than a fixed ±15%. The load governor compares the lower bound of the forecast against the budget. The choice between model and observed stays provisional until V-field.
- ldi_params@v1 is NOT confirmed by SP-3. Take it out of SP-3's freeze claims (convergence §4.7 and DEC-CNV-03) and assign the parameter sensitivity analysis to SP-6 or a simulator follow-up.
- Add determinism tests for the incremental correction path (append(correction), and merges that include corrections from another device) to the INT-1 gate. Use SQLite WAL with synchronous=FULL for the ledger DB.

## SP-4 — PARTIAL

### 불일치·과대주장 (Discrepancies)
- Short-query (1-2 char Korean) recall 0.991 is circular. For 12 of 14 short queries, the rel set equals the set of docs that literally contain the query substring, and the 6 'ground-truth audit' additions were literal-containing docs too. An unranked substring oracle (corpus reverse order) scores the same 0.991 as V2. So the metric only shows that instr() finds substrings and says nothing about ranking. The claim that it satisfies the FR-CUR-011 '2-syllable subset >= 0.8' criterion is withdrawn. The metric is unverified until DCP-01. Only 트리 (P@10 0.70) and 락 (P@10 0.60) carry signal, and the 310-doc corpus rarely forces top-10 truncation.
- The claim that default-rate backup() never completes under a full-speed writer (20s, 36,702 rewinds) is nondeterministic. The rerun completed in 303ms after 608 rewinds, and rate:1000 completed in 179ms. The correct statement is 'completion time unbounded', not 'always fails'.
- The C1 same-file claim 'p99 ~10x (1.5ms)' was not reproduced (rerun p99 0.15-0.17ms). C2/C3 error counts varied several-fold (5,969 -> 48,344; 4,404 -> 29,271). Only the direction reproduced (deferred-upgrade and busy_timeout=0 produce BUSY errors).
- The stated run-to-run variance of +/-10-20% is understated. Single-writer baseline went 14,599 -> 25,683 txn/s, prepared-statement reuse ratio 6.7x -> 3.5x, search p95 at 12,310 docs 25.3 -> 17.2ms, B1 commit max 64 -> 293ms.
- The escape testing was narrower than claimed. Only CI/CD unquoted vs quoted was tested. The audit added embedded-quote and FTS-operator inputs; none threw, so quoting is safe. However, punctuation is not stripped from tokens: '(쿠버네티스' and a user-typed '"캐시"' return 0 results.
- The claim 'instr instead of LIKE gives identical results' was never tested in the spike code (the metric named *_via_like_scan actually uses instr). The audit found it holds only when the query has no wildcards: LIKE returns all 310 docs for '%' and '_'.
- Reproduced exactly or within tolerance: B1/B2 BUSY/LOCKED = 0 (753,824 commits, reader 4,737 reads with 0 errors and 0 torn batches); C1 BUSY = 0; C4 timeout honored (~3,008ms); SIGKILL recovery integrity ok; recall@10 for all variants and sets identical to 3 decimals; FTS5 mechanism facts identical; 21/21 warning-suppression cases identical, all exiting 0 with stdout OK; VACUUM INTO under a live writer ok; 0 SIGSEGV in the full rerun.

### 구속 결정 (Binding decisions)
- One SQLite file per service, owned by exactly one service process (NFR-MAINT-002). No cross-service file access or ATTACH, enforced by static check. Separate files showed 0 BUSY/LOCKED even with busy_timeout=0.
- Every connection is opened through a SqlitePort adapter factory with timeout: 5000, because node:sqlite defaults busy_timeout to 0. Writers set PRAGMA synchronous=NORMAL. journal_mode=WAL is set once at DB creation or migration. Constructor option keys are whitelisted because unknown options are silently ignored.
- All writes go through a tx() helper using BEGIN IMMEDIATE. A deferred BEGIN followed by a read and then a write upgrade is forbidden: busy_timeout is bypassed and BUSY/BUSY_SNAPSHOT (517) errors result. Write transactions must stay short (no await or external calls inside), since a waiter fails exactly at busy_timeout.
- Auxiliary tools (seed/restore/doctor) may write to a service's file only under the BEGIN IMMEDIATE rule. The single-writer rule is convention plus safety net, not a hard lock.
- Read-only consumers open with readOnly:true. WAL snapshot reads do not block writers, so a dedicated search read-replica fallback is not needed.
- Errors are classified by errcode & 0xff (5 = BUSY, retryable; 6 = LOCKED). Error .code is always ERR_SQLITE_ERROR. errcode 517 is treated as a code-defect signal.
- Bind values are type-checked in the adapter (number/string/bigint/Uint8Array/null only), because a Date silently binds as NULL and boolean/undefined throw. Tables use STRICT and CHECK(json_valid()). Booleans are INTEGER 0/1, times are epoch-ms INTEGER, and IDs are ULID TEXT.
- Korean search uses hybrid V2: NFC+lowercase normalization at both index and query time; FTS5 trigram with every token double-quoted (embedded " doubled) for tokens of 3+ characters; instr() scan (not LIKE) for tokens under 3 characters; plus whitespace-stripped, josa-stripped and IDF-weighted OR stages. Raw trigram alone (V0, 0.467) is insufficient. Query tokens must additionally be stripped of punctuation and quote characters (an audit-found defect).
- Keep a switch to move the short-token path to V3 (unicode61 prefix) when the corpus grows. Set the threshold conservatively (well below ~40k docs) because latency varied up to ~1.5x between runs.
- The 2-syllable recall subset (FR-CUR-011) is NOT validated by SP-4 because its rel sets were circular. DCP-01's 120-query eval must include short queries with many literal hits (more than 10) and ground truth that is a strict subset of the literal matches, and must measure precision@10 as well as recall.
- Content lint requires an English alias or synonym for every Korean concept. Vocabulary gaps caused most of the remaining recall loss.
- Backups use VACUUM INTO a temp path, then rename, then integrity_check on the copy. Do not rely on default-rate backup() under live writes (completion time unbounded). Never close the source DB while a backup() promise is pending. Run backup and bulk jobs in a separate process.
- ExperimentalWarning is suppressed with --disable-warning=ExperimentalWarning on every node/tsx invocation. The supervisor merges the flag into env.NODE_OPTIONS for spawned children, because spawn does not inherit execArgv. The entry point wraps process.emitWarning and then dynamically imports node:sqlite. Do not use --no-warnings, NODE_NO_WARNINGS, removeAllListeners, or process.on('warning') (which does not suppress). E2E checks the stderr of every service process.
- Supervisor auto-restart plus integrity_check after a crash. Graceful shutdown goes through HTTP/IPC calling db.close(), not signals, for Windows. Add a doctor warning for Node 22 EOL and experimental node:sqlite.
- Windows/macOS support is NOT established. Windows CI/V-live (paths, mandatory locks, AV locks, -shm, MAX_PATH, shebang) is a gating follow-up before the 'both OS' criterion can be marked PASS. The data dir defaults to %LOCALAPPDATA%\Fathom, with warnings for sync, network and WSL paths.

## SP-6 — PARTIAL

### 불일치·과대주장 (Discrepancies)
- Reproduction is exact. npm test passed 15/15 and typecheck passed. The re-run of npm run spike produced result.json (ignoring elapsedSec) and matrix.md byte-identical to the committed ones. Every number in report sections 4.1 to 4.7 matches result.json. Runtime was 74s here against 111s in the report, which is a hardware difference only.
- Overclaim on criterion (2), random-agent theta rise <= 0.02: the reported '0% above 0.02' counts only concept-runs with at least 30 events (run.ts finals30), and that filter removes exactly the runs that break the criterion. Re-running with the spike's own seeds, 19 of the 54 excluded concept-runs exceed +0.02 at day 60: random FULL 6/5052 (max +0.27), random LLM_ONLY 4/2526 (max +0.44), random_ox FULL 6 (max +0.21), random_ox LLM_ONLY 3 (max +0.18). The report does not disclose this.
- The report claims a 'session-level PASS', but the spike never measured theta at session level. An audit run over a one-day horizon shows random_ox with 9.1% of concept-runs (656/7248) above +0.02, max +0.94. Mixed-format guessing is at 0.1% (max +0.32). The criterion holds only asymptotically, so the correct verdict for (2) is PARTIAL, not PASS.
- Section 4.7 says the 12-item deterministic assessment is what blocked gamer promotion. That is false: gamer_seq OFFLINE made 0 assessment attempts in all 456 runs (all not_ready). The runs were stopped at G1_required_concepts (192) and G1_sparse_depth_evidence (264). The sparse-depth gate is a sim hardcode (agent.guess ? 0 : 1), not a rule outcome. Promotion 0 still holds analytically, but the simulation did not show it.
- Section 4.2 says the structural analysis and the simulation agree on the 40 unreachable combos, but runMatrix never simulates X cells. The audit ran the ideal learner on all 30 distinct X cells (5 seeds, 200 days) and got 0/150 reached, so the claim holds, but this audit is the first check of it.
- The F4 'no side-effect on honest learners' claim (sections 4.8 and 6.1) rested on a confounded comparison: policy A against C, where C also adds F1, F3 and the Brief. An isolated audit of A against A+F4 on the same inventory gives ideal 3900/3900 for both (260 provisional each) and realistic 3490 against 3477 (-0.3pp). The claim holds.
- Criterion (1a), 'provisional only in OFFLINE', is true by construction rather than an emergent result: sim.ts hardcodes provisional:false for Case and D4 evidence in every non-OFFLINE mode.
- The SP-1-fail modeling differs from the fallback pre-agreed in CNV. The fallback makes Jev gate/classify-only and gives BPS and rubric grading to LLM-judge. The spike instead lets uncalibrated Jev (0.7) grade Case, Teaching and Artifact rubrics. JUDGE_ONLY has no LLM, so under the fallback its SP1-fail T3/T4 descriptive evidence would probably be self-graded, i.e. provisional. The 'C' status of those cells and the 'SP-1 changes nothing' statement are therefore unverified for status, though reachability likely still holds.
- Minor: the ideal learner is described as having 'no mis-grading', but the code has 5% self-grading FP and FN, 5-10% judge flips and a D4 success rate of 0.95. The note that FULL caps are 'L5 for all but arch' is wrong, because the six cap-L4 tracks stay at L4. The 'reach 0.84-1.00' figure for the realistic learner is a mean; the worst cells are 0.47 (policy C) and 0.50 (policy A).
- Criterion (3), random Mastered 0, is confirmed and strengthened. P >= 0.8 would need a peak rise of at least 1.886, and the highest peak observed under policy A is +1.01, so Mastered is impossible even mid-trajectory, not only at the end of a run.

### 구속 결정 (Binding decisions)
- F0: the Elo update must use guess correction, P = c + (1-c)*sigmoid(theta - beta) with c = 1/n_options (0 for open answers). n_options is stored as item metadata. Without it, an agent that only guesses OX items raises theta by +0.50.
- F4: the system acts on an effective theta = min(theta_all, theta_q), where theta_q is updated only by events with w_format >= 0.7 AND w_grader >= 0.6. Mastered P, LDI and adaptive difficulty all consume effective theta. Record theta_q rules under policy_version.
- Format counting uses two conditions (DEC-CNV-19), not a product: correct && !pending && gaming>0 && w_format>=0.7 && w_grader>=0.6. Every threshold comparison uses an epsilon geq, which matters at boundaries like 27/36 vs 0.75 and LLM-judge 0.6.
- Adopt F1 (a level with no concepts is skipped, so the track starts at its first non-empty level) and F3 (D4 required = max(min(2, possible), min(5, possible))). Reject F2 (borrowing items from the adjacent level) as weak evidence.
- The FR-CUR-025 cap oracle must include the per-level assessment pool (at least 12 items and at least 4 formats from engines allowed in each AI mode). Implement structuralFeasibility(policy, inventory, transition, mode, sp1) as a pure function. Reuse it for the promotion screen's missing-condition list, for pack reports, and as a CI gate on every pack change (pack lint R-POOL).
- Until Brief content exists (one extra Tier B concept each for docker/cicd/cloud/ml/eng L4 and lead L2/L3; about 2 each recommended), the product map shows oracle caps (docker/cicd/cloud/ml/eng = L4) rather than the declared caps. Replace the assumed Tier B allocation with real required_for_level data and re-run the feasibility gate.
- Theta safety holds only with enough evidence. Do not show concept theta in the UI and do not feed it to LDI or promotion decisions until the concept has at least 30 graded events, or apply prior shrinkage. Restate SP-6 criterion (2) as 'theta rise <= 0.02 after >= 30 graded events per concept', and run the regression test over all concept-runs without an exposure filter.
- decidePromotion returns a profile (policy version, AI mode, SP-1 state) and a gates[] array for the FR-PRG-033 decision card. reconcileProvisional never demotes (BR-14): a revoke emits provisional_revoked with needs_reconfirmation.
- Promotion assessment: 12 items drawn round-robin across formats, only from deterministic formats plus calibrated-Jev formats when SP-1 passes, with at least 4 formats. All thresholds (requiredMasteredRatio, cbmMin, the D4 rules, the Case gates, l5) live in the mastery_rules policy file and are passed as arguments to pure functions.
- Open decisions to settle before freeze: (a) the rubric engine for JUDGE_ONLY when SP-1 fails, i.e. whether that evidence is provisional under the CNV SP-1 fallback; (b) the CBM rule, since 70% and 75% are equivalent at 12 items and an all-C2 perfect learner fails; (c) the 85% required-concept ratio, which means 100% for n <= 6; (d) the sparse depth-evidence scope (track vs level) and the D4 concept scope.

### 구속 결정 (Binding decisions)

- check:boundaries runs with --engine=both (tokens plus the tsgo typescript/unstable/sync module resolution) as the CI default. typescript is pinned exactly to 7.0.2 (no caret) because the API is unstable. Upgrading TS requires the gates to pass.
- Required when porting (audit fix): every gate catches engine exceptions and exits 2. A violation exits 1, clean exits 0.
- Required when porting (audit fix): every gate exits 2 when it scanned 0 files. It should also assert that the expected unit directories (services/*, packages/contracts) exist, to prevent a vacuous pass.
- Required when porting (audit fix): the check:gates runner must not fall back from both to tokens when tsconfig.json is missing. It exits 2 unless an explicit opt-in flag is given.
- Do not side-pin TS 5.9/6.x for the gates. The fallback is not triggered. typescript-eslint, dependency-cruiser (TS path) and madge are not adopted: dependency-cruiser false-passes with modules=0 under TS 7 alone. If one is ever needed, it lives only in a tools/ workspace with the typescript=@typescript/typescript6 plus typescript7 alias pair, and needs its own spike.
- The SQL gate uses the tokens scanner as its primary engine. The tsgo type-based check-sql-typed is the recommended second engine; it catches db['prepare'], .bind and .call and rules out RegExp#exec by type. The escape hatch `// sql-ok: <reason>` (or biome-ignore lint/plugin: <reason>) must carry a reason.
- Freeze these code conventions in STD-01, since the gates depend on them: workspace/paths aliases only as @fathom/svc-*, @fathom/app-* or @fathom/<pkg>. Jev code in services/*/src/jev/ or *.jev.ts, with prompts in jev/prompts/*.md, referencing items by object key only. SQL as literals with ?/:name binding, plus ident()/placeholders()/sqlInt()/UPPER_SNAKE constants. Pre-submit schemas in pre-submit/ or *PreSubmit* as separate zod objects with no spread or extend from post-submit. Blank-note code in blank-note/ (post-submit code in blank-note/post-submit/). ai-gateway-policy.ts keeps deny_before_submit ['blank_note.*']. Raw colors only in packages/design-tokens/. Routing code in routing/ or *.route.ts. Dynamic import(variable), createRequire and require are banned unless marked with `// boundary-ok: <reason>`, and CI promotes the nonliteral-import warning to an error.
- The static gates are a safety net against accidental violations, not a security boundary. The real enforcement stays with contract tests (FR-QST-022 403) and runtime refusal (the gateway policy for FR-STD-018, read-only DB connections). NFR-UX-008 verification should be reclassified: G1, G4, G5 and G6 can be checked statically; for G3 and G7 static checks are secondary; G2's 'no other-user concept in schema' check stays on the review checklist.

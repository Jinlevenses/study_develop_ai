## 4. 동작 규약

### 4.1 YAML 공통 규칙

1. 파일 = `policy/<name>@v1.yaml`, 첫 줄 주석 `# file: policy/<name>@v1.yaml   (owner: <svc> · zod: packages/contracts/src/policy/<name>.ts)`, 둘째 줄부터 본문. 잠정 정책은 셋째 줄에 `# provisional: <사유·확정 시점>` 주석(해시 무관 — 해시는 파싱 결과 JSON 기준).
2. `parseYamlStrict` 통과 형식만: YAML 1.2 core 스키마, **앵커·별칭(`&`/`*`)·병합 키(`<<`)·사용자 태그(`!!binary` 등)·중복 키 0**, `__proto__`·`constructor`·`prototype` 키 0. 숫자 키(레벨 `'1'`~`'5'`)는 **따옴표 문자열**로 쓴다. 정규식·특수문자 문자열은 작은따옴표(내부 `'`는 `''`). `1e-9`처럼 지수 표기는 `1.0e-9`로 쓴다.
3. 최상위 `version: <name>@v1` 필수(zod literal). 전수 record(zod 4 — 키가 enum이면 **모든 키 필수**): `method_policy.formats`(FormatId 33)·`router_25`(D·C·P·S·M × '1'~'5')·`router_25.*.*.bloom`(6)·`level_mix.groups`(6)·`level_mix.shares`(5 × 6) · `gaming_params.t_min_ms_by_format`(33) · `composer_policy.peak_end.wave`(SlotId 6) · `mastery_rules.ai_profiles`(AiMode 4)·`assessment.accuracy_min_correct`·`cbm_min`(4) · `ai_policy.cache_ttl_days.per_task`(35 = AI-J01~J19 + AI-G01~G13 + SYS-CANARY·SMOKE·FWCLS). 비율 합 = 1(±1e-9) 검사 대상: `bloom` 각 칸·`level_mix.shares` 각 레벨·`gate_thresholds` `bps.w`·`teaching.w`.

### 4.3 `tools/packc/src/policy/lock-cli.ts` (PGM-PACKC-010, ARC §10.4, DCP §6.16)

```ts
export const POLICY_OWNERS = {                      // IF-01 §13.4 표 소유 열 — 12종 정확히
  method_policy: 'learning', composer_policy: 'learning', mastery_rules: 'learning', ldi_params: 'learning',
  gaming_params: 'learning', cbm_params: 'learning', fsrs_params: 'learning',
  gate_thresholds: 'content', search_params: 'content',
  ai_policy: 'ai-gateway', firewall_rules: 'ai-gateway', ops_policy: 'ops-api',
} as const satisfies Record<string, ServiceNameT>;
export const POLICY_SCHEMAS: { readonly [K in keyof typeof POLICY_OWNERS]: z.ZodType };   // 정적 import 12개(MethodPolicyV1 … OpsPolicyV1)
export type LockProblem = { readonly file: string; readonly reason: 'bad_filename' | 'unknown_policy' | 'yaml_error' | 'version_mismatch' | 'schema_invalid'; readonly detail: string };
export function computeLock(policyDir: string): Result<PolicyLockT, readonly LockProblem[]>;
export function serializeLock(lock: PolicyLockT): string;                                   // 키 정렬 + JSON.stringify(_, null, 2) + '\n'
export function diffLock(expected: string, actualText: string | null): readonly string[];  // 'stale <ref>' · 'missing <ref>' · 'extra <ref>' · 파일 없음 = 'missing policy.lock.json'
export function main(argv: readonly string[]): number;                                       // 0 · 1 · 2
```
- **스캔**: `<policyDir>`의 `*.yaml` 파일만(하위 디렉터리 0). 파일 이름 `^([a-z][a-z0-9_]{2,40})@v(\d{1,4})\.yaml$` 불일치 → `bad_filename` · 이름 ∉ `POLICY_OWNERS` → `unknown_policy` · `parseYamlStrict` 실패 → `yaml_error` · 최상위 `version` ≠ `<name>@v<k>` → `version_mismatch` · `k === 1`이면 `POLICY_SCHEMAS[name].safeParse` 실패 → `schema_invalid`(detail = 첫 이슈 `path.join('.')` + message; `@v2+`는 스키마 버전 파일이 생길 때까지 검사 생략 — `notes`) → 성공 항목 `{ [ref]: { sha256: policyContentHash(value), owner: POLICY_OWNERS[name] } }`. 문제 1개라도 있으면 `err(전부)`.
- **직렬화**: 최상위 키 = ref 사전순, 항목 키 순서 `owner` → `sha256`(사전순), 2칸 들여쓰기, 끝 줄바꿈 1개. `PolicyLock.parse` 통과 후에만 쓴다. 결과는 biome JSON 포맷과 같아야 한다(`pnpm lint`가 확인 — 다르면 직렬화를 biome 출력에 맞춘다, 파일을 손으로 고치지 않는다).
- **`main`**: 인자 없음 = 계산 → `<policyDir>/policy.lock.json` 원자적 쓰기(`*.tmp` 후 `renameSync`) → stdout `policy:lock files=<n> written` → 0. `--check` = 쓰지 않고 `diffLock` → 차이 0이면 `policy:lock files=<n> ok` → 0, 아니면 줄마다 출력 → **1**. 정책 문제 → 줄마다 `error <file> <reason> <detail>` → **1**(쓰기 0). `--dir <abs>`(테스트 전용) = 읽기·쓰기 위치 교체(기본 = 저장소 `policy/` = `fileURLToPath(new URL('../../../../policy/', import.meta.url))`). `*.yaml` 0개·디렉터리 없음·알 수 없는 인자·예외 → stderr 한 줄 → **2**(빈 입력 = 엔진 고장, CLAUDE.md §4 게이트 관례).
- 엔트리 판정: `import.meta.url === pathToFileURL(process.argv[1] ?? '').href`일 때만 `process.exitCode = main(process.argv.slice(2))`(테스트 import 시 부작용 0, STD-TS-15). 시계·난수·환경변수 0 → 같은 입력 = 같은 바이트.

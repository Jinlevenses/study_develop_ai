### 4.0 공통 [Brief 결정]

1. **시계·난수 주입**: `lib/`의 시간 의존 함수는 `now: () => number`(epoch ms)를 인자로 받는다. `Date.now()`는 **`main.tsx` 한 곳**(조립 루트)에서만 쓴다(STD-TS-20 — web은 표시 계층이지만 테스트 결정성 유지). ID·키 난수 = Web Crypto `crypto.getRandomValues`(STD-TS-21의 브라우저 대응, `Math.random` 0).
2. **브라우저 영속 저장소** — STD-WEB-14(localStorage 금지)와 DS-01 DN-D5·SCR DN-05(테마·모자·키맵·Context 패널 상태 = `localStorage`)가 충돌한다. **결정**: `localStorage` 접근은 `lib/ui-prefs.ts` **한 모듈**(+ `public/theme-init.js`의 `fathom.theme` 읽기 1곳)에만 두고, 허용 키 = `fathom.theme`·`fathom.hat`·`fathom.keymap.v1`·`fathom.suggest.home.dismissed_at`·접두 `fathom.ctx.`(값 ≤ 4,096자 문자열). 토큰·CSRF·서버 데이터는 절대 쓰지 않는다(STD-SEC-26). `sessionStorage`·쿠키 직접 쓰기 0. 다른 파일의 `localStorage`·`sessionStorage`·`document.cookie` 문자열 0(UT-WEB-036이 src 전체를 텍스트 스캔). **CR 후보**(T1): STD-WEB-14에 "UI 기기 선호 키 예외(DS DN-D5)" 구체화.
3. **네트워크 진입 단일화**: `fetch`는 `lib/api-client.ts`, `EventSource`는 `lib/sse.ts`에서만(STD-WEB-12). 둘 다 **주입 가능**(`fetch: typeof fetch`, `EventSourceCtor`) — 테스트는 가짜를 넘긴다(실네트워크 0, STD-TST-04).

### 4.1 WP-00-25 ① 계약 클라이언트 — `lib/{idempotency,api-client,csrf,query-client,router-context}.ts` (PGM-WEB-003)

**`idempotency.ts`**
```ts
export function newUlid(now: () => number, random?: (bytes: Uint8Array) => Uint8Array): string;   // 기본 random = crypto.getRandomValues
export function createUlidFactory(now: () => number, random?: …): () => string;                  // 같은 ms 안에서 단조 증가(무작위부 +1, 80비트 넘침 = throw)
```

- 형식 = Crockford base32 26자(`^[0-9A-HJKMNP-TV-Z]{26}$`), 앞 10자 = 48비트 시각. `now()`가 음수·비정수·2^48 이상 → `RangeError`.

**`api-client.ts`** (STD-WEB-12, IF §2.2·§2.5·§2.7)
```ts
export type ApiFailure =
  | { readonly kind: 'problem'; readonly status: number; readonly problem: ProblemT }
  | { readonly kind: 'network'; readonly message: string }
  | { readonly kind: 'contract'; readonly status: number | null; readonly detail: string };
export type ApiResult<T> = { readonly ok: true; readonly status: number; readonly data: T; readonly replayed: boolean } | ({ readonly ok: false } & ApiFailure);
export class ApiError extends Error { readonly failure: ApiFailure }                 // TanStack Query queryFn용
export function isRetryable(f: ApiFailure): boolean;                                 // network → true · problem → problem.retryable · contract → false
export interface ApiClientDeps {
  readonly fetch: typeof fetch; readonly csrf: CsrfStore; readonly newKey: () => string;
  readonly onSessionLost?: (code: string) => void; readonly onVersionMismatch?: () => void;
}
export interface ApiClient {
  call<R extends RouteDef>(route: R, input: RouteInput<R>, opts?: { readonly idempotencyKey?: string; readonly signal?: AbortSignal }): Promise<ApiResult<RouteOutput<R>>>;
  query<R extends RouteDef>(route: R, input: RouteInput<R>, opts?: { readonly signal?: AbortSignal }): Promise<RouteOutput<R>>;   // 실패 = throw ApiError
}
export function createApiClient(deps: ApiClientDeps): ApiClient;
```
- `RouteInput<R>` = `{ params?: z.input<params>; query?: z.input<query>; body?: z.input<body> }`(각 키는 라우트 정의에 그 스키마가 있을 때만), `RouteOutput<R>` = `R['response']`의 2xx 스키마들의 `z.output` 합집합(204 = `null`). 타입 구현이 막히면 입력을 `Record<string, unknown>`으로 낮추고 `deviations[]`에 적는다(런타임 검증은 그대로).
- **요청 조립**: ① `params`·`query`·`body`를 라우트 스키마로 `safeParse`(실패 → 네트워크 0, `{kind:'contract', status: null, detail: '<request.params|query|body> <첫 이슈 경로>'}`) ② URL = `route.path`의 `{name}`을 `encodeURIComponent(String(params[name]))`로 치환(`:verb` 접미 유지), query는 파싱 결과의 `undefined` 아닌 키를 사전순으로 `URLSearchParams`(배열은 같은 키 반복) — **상대 URL**(`/api/v1/…`, origin 미포함) ③ 헤더: 항상 `accept: application/json`·`x-fathom-client: CLIENT_HEADER` · body 있음 → `content-type: application/json; charset=utf-8` + `JSON.stringify(parsed)` · method ∈ {POST, PUT, PATCH, DELETE} ∧ `csrf.get() !== null` → `x-fathom-csrf` · `route.idempotent` → `idempotency-key: opts.idempotencyKey ?? newKey()`(GET·비멱등 라우트에는 붙이지 않음) ④ `fetch(url, { method, headers, body, credentials: 'same-origin', signal })`.
- **응답 판정**: fetch가 던짐 → `network`(메시지만) · 2xx → `response[status]` 스키마로 parse(없는 상태·실패 → `contract`), 204 → `data: null`, `replayed` = 헤더 `idempotent-replayed === 'true'` · 4xx/5xx + `content-type`이 `application/problem+json` → `Problem.safeParse`(실패 → `contract`) → `problem` · 그 밖 → `contract`.
- **부수 처리**(결과는 그대로 반환): 401 ∧ code ∈ {`GW-AUTH-001`, `GW-AUTH-003`} → `onSessionLost(code)` · 409 ∧ `GW-CONFLICT-010` → `onVersionMismatch()` · 403 ∧ `GW-AUTH-002`(CSRF 불일치) → `SessionCsrfRoute` 1회 재조회 후 `csrf.set` → 원 요청을 **같은 멱등 키로 1회만** 재시도.
- **자동 재시도 없음**(위 CSRF 1회 제외) **[Brief 결정]**: 조회 재시도는 Query 정책(`query-client.ts`), 제출 재시도는 attempt 큐가 맡는다.

**`csrf.ts`**: `export interface CsrfStore { get(): string | null; set(v: string): void; clear(): void }` + `createCsrfStore(): CsrfStore` — **메모리만**(STD-SEC-26), `set`은 `^[A-Za-z0-9_-]{43}$` 아니면 `TypeError`.

**`query-client.ts`**: `createQueryClient(): QueryClient` — `defaultOptions.queries = { staleTime: 30_000, refetchOnWindowFocus: false, retry: (count, err) => count < 3 && err instanceof ApiError && isRetryable(err.failure), retryDelay: (n) => Math.min(30_000, 1000 * 2 ** n) }`, `mutations.retry = false`.

**`router-context.ts`**: `export interface RouterContext { readonly queryClient: QueryClient; readonly api: ApiClient }`(라우터·`__root.tsx` 순환 import 방지용 타입 파일).

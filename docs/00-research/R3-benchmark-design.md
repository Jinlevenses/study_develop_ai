## 0. 결론 요약 (TL;DR)

1. **빈 자리(gap)는 명확하다.** 15개 벤치마크 중 "전 분야 지식 지도 + 검증된 숙달(mastery) + 간격반복 + 자동 문제생성 + 실행형 실습 + 백지 회상 + 전문가(L5) 깊이 + 로컬 우선"을 동시에 가진 서비스는 없다. roadmap.sh는 **지도만**, Anki는 **기억만**, LeetCode/프로그래머스는 **알고리즘만**, 인프런/Frontend Masters는 **시청만**, Obsidian은 **노트만** 한다. 우리 제품의 정체성 = **"지도(roadmap) 위에서 숙달을 증명하는 로컬 학습 OS"**.
2. **코어 루프는 5중 루프**로 설계한다: 세션(15~25분) → 일(Daily Queue) → 주(약점 리포트) → 시즌(6~8주 섹션×레벨 목표 + 회고) → 커리어(연 단위 Depth Map). Duolingo의 짧은 세션·즉시 피드백은 차용하되 **불안 기반 스트릭은 거부**(15년 사용 가정, UR-12).
3. **숙달은 자기보고가 아니라 증거로.** roadmap.sh의 "Done 체크"가 가장 큰 약점. 노드 완료 = FSRS 안정도(stability) + 레벨별 문항 정답률(~75% 밴드, R2) + 백지노트 KU 커버리지(Jev 판정)의 합성 지표.
4. **디자인 방향 3안** — D1 *Graph Paper(모눈노트)*, D2 *Reading Room(열람실)*, D3 *Bathymetry(수심도)*. **D3 추천**: 쿨 슬레이트 다크 우선, 색은 오직 **깊이(L1~L5)와 상태**만 인코딩. 시그니처는 홈의 **Depth Map**(섹션 × 레벨 숙달을 해저 지형처럼 보여주는 단 하나의 기억되는 요소). 나머지는 조용하고 밀도 높게.
5. **색 체계는 OKLCH 12역할 토큰**으로, 모든 텍스트/비텍스트 대비를 계산으로 검증했다(§6.4 `[실측]`, WCAG 2.2 AA 전 항목 통과, sRGB gamut 내).
6. **타이포**: UI/본문 = Pretendard Variable(한글+Inter 계열 라틴이 한 몸이라 혼용 이질감 없음), 코드 = JetBrains Mono + **D2Coding 한글 폴백**, 표시용 라틴 숫자·헤딩 보조 = Geist. 모든 폰트는 **self-host**(로컬/오프라인 앱, CDN 금지).
7. **키보드 우선 + 한국어 IME 대응**이 품질 차별점: 단축키는 `event.code` 기반(한/영 상태 무관), Enter는 `isComposing` 가드, cmdk 필터에 **초성 검색**(es-hangul) 결합.
8. **운영성(UR-17)**: 토큰 = 단일 소스(`tokens.css` @theme) → UI 표준정의서 자동 표 생성, 대비 lint 스크립트, Playwright 스크린샷 회귀, `/_design` 살아있는 스타일가이드 라우트.

## 1. 분석 프레임

각 서비스를 다섯 축으로 분해하고, 우리 요구(UR)에 대한 교훈으로 환원한다.

| 축 | 질문 |
|----|------|
| Core loop | 사용자가 매번 반복하는 최소 행동 단위는? 무엇이 트리거하고 무엇이 보상하는가? |
| Study modes | 어떤 인지 활동(인출·정교화·적용·생성·설명)을 지원하는가? |
| Progression | 성장을 어떻게 정의·가시화하는가? 자기보고인가 증거인가? |
| Stickiness | 무엇이 재방문을 만드는가(외재/내재 동기, 손실회피, 사회성, 소유)? |
| Weakness | 장기(15년) 학습자 관점에서 무엇이 무너지는가? |

학습과학 렌즈(교훈 도출 시 기준): **인출 연습(retrieval practice)**, **간격 효과(spacing)**, **교차 학습(interleaving)**, **정교화(elaboration)**, **생성 효과(generation effect)**, **바람직한 어려움(desirable difficulty)**, **스캐폴딩 페이딩(worked-example fading)**, **자기결정이론(SDT: 자율성·유능감·관계성)**.

## 4. 도출된 코어 루프 (Core Loop 설계 입력)

```
[세션 루프 15~25분]  ─ 오늘 큐 열기(Ctrl+K "오늘") 
   ① 워밍업: due 복습 5~10개 (OX/빈칸/출력예측 — 빠른 인출)
   ② 신규 또는 디깅: 이론 → 코드 → 핵심 개념 (UR-10)  |  or 프리테스트 먼저(BL-08)
   ③ 인출 믹스: 레벨 맞춤 문항 5~8개, 교차(interleaving) — 유형 로테이션 규칙 적용
   ④ 백지노트 1개: 방금 개념을 빈 화면에 → Jev KU 커버리지 맵(초록/회색/빨강)
   ⑤ 세션 리포트: 안정도 변화·깊이 변화·다음 추천 (유일한 축하 모션)
[일 루프]   Daily Queue = due 복습 + 약점 KU + 시즌 목표 개념 (상한/로드밸런싱)
[주 루프]   주간 리포트: 약점 개념 Top5, 오개념 패턴, 모드 편중 경고 → 다음 주 계획 제안
[시즌 루프] 6~8주: 섹션×레벨 목표 → 주간 체크 → 시즌 회고(방향성·구현성 자가평가, UR-03 동형)
[커리어 루프] 연 단위: Depth Map 변화(과거 오버레이), L1→L5 여정, 포트폴리오(ADR·포스트모템 답안) export
```

**모드 로테이션 규칙(질림 방지, UR-14)** — 같은 모드 연속 3회 금지, 세션 내 인지 활동 최소 3종(인출·적용·생성), 주 1회 이상 "디깅"과 "실습", 연속 오답 3회 시 모드 강등(서술 → MCQ → OX)과 힌트 사다리 자동 제안.

### 5.3 비(非)제네릭 원칙 — "AI가 만든 것 같은 룩" 회피 체크리스트

Anthropic `frontend-design` 스킬(`[실측]` GitHub raw)의 캘리브레이션 목록과 업계 관찰을 합쳐, 아래를 **기본값으로 쓰지 않는다**.

- [ ] 흰 배경 + 보라/인디고 그라데이션 히어로, 크림(#F4F1EA) + 세리프 + 테라코타 액센트
- [ ] 근흑 배경 + 단일 형광 그린/버밀리언 액센트("해커 터미널" 클리셰)
- [ ] 동일 반경·동일 그림자(rgba(0,0,0,.1))의 카드 격자로 모든 콘텐츠를 자르기
- [ ] 모든 제목 위의 ALL-CAPS 트래킹 eyebrow 라벨, `A · B · C` 메타 문자열, 버튼 텍스트 끝 `→`
- [ ] 작은 데이터 라벨에 모노스페이스 남용 (숫자는 Pretendard `tabular-nums`로)
- [ ] 의미 없는 `01 / 02 / 03` 번호 (진짜 순서일 때만: 세션 단계, 절차형 문항)
- [ ] 섹션마다 fade-and-slide-up 등장, 모든 카드 hover 리프트
- [ ] 헤드라인의 한 단어만 색/이탤릭 강조

**대신 할 것** — 주제(개발 학습의 "깊이")에서 시각 언어를 끌어낸다: 수심·지층·등고선. 대담함은 **한 곳(Depth Map)**에만 쓰고, 나머지는 절제한다.

## 6. 후보 디자인 방향 3안

> 모든 OKLCH 값은 sRGB gamut 내이며, 대비는 WCAG 2.x 상대휘도 공식으로 계산했다(`[실측]` 스크래치 스크립트: OKLCH → linear sRGB → 상대휘도). 표기: `oklch(L C h)`.

### D3. Bathymetry — 수심도 (쿨 슬레이트 다크 우선) ★ 추천

- **컨셉**: 학습의 깊이 = 수심. 초급은 얕은 여울(밝은 청록), 전문가는 심해(깊은 남보라). 서비스 전체에서 **색은 오직 깊이(L1~L5)와 상태(정답/오답/due/포커스)만** 뜻한다. 복습 due는 "수면으로 떠오른" 개념.
- **무드**: 차분함, 정밀함, 탐사. 해도(nautical chart)의 등심선처럼 **데이터가 곧 장식**.
- **시그니처 1개**: 홈의 **Depth Map** — 섹션(열) × 레벨(L1~L5, 위→아래 깊어짐)의 숙달을 등심선/지층 형태로 그린 차트. 과거(3/6/12개월 전) 오버레이로 "얼마나 깊어졌는가"를 보여준다. 이것이 UR-11/12(초급→15년차)의 시각적 서사다.

#### D3 모션 규칙

| 토큰 | 시간 | 이징 | 용도 |
|---|---|---|---|
| `dur-instant` | 90ms | `cubic-bezier(.2,0,0,1)` | hover·press 상태색 |
| `dur-fast` | 150ms | 동일 | 툴팁·메뉴·토글 |
| `dur-base` | 220ms | `cubic-bezier(.2,0,0,1)` / exit `cubic-bezier(.4,0,1,1)` 160ms | 패널·다이얼로그·Peek |
| `spring-card` | — | Motion `{type:"spring", bounce:0.12, duration:0.35}` | 플래시카드 뒤집기, 순서배열(Parsons) 재정렬 |
| `dur-moment` | 600~900ms | 오케스트레이션 1회 | **세션 리포트의 "떠오름"**(깊이 게이지 상승) — 서비스 유일의 연출 |

1. 모션은 **사용자 행동의 결과**를 보여줄 때만(채점, 뒤집기, 저장, 재정렬). 페이지 진입 연출·스크롤 등장 금지.
2. 채점 피드백: 정답 = 테두리 `--correct` 150ms + 체크 아이콘, 오답 = `--incorrect` + **흔들기 금지**(조롱 느낌·전정기관 부담) → 오개념 태그가 슬라이드 인.
3. `prefers-reduced-motion: reduce` → `MotionConfig reducedMotion="user"` 전역 + CSS에서 transform 제거, opacity 크로스페이드(≤120ms)만 유지.
4. 로딩: 300ms 미만은 표시 안 함, 이상은 스켈레톤(쉬머 금지, 정적 톤), LLM 스트리밍은 토큰 단위 표시 + 취소(`Esc`).

### 6.2 추천: D3 Bathymetry — 근거

1. **색의 의미가 제품의 핵심 축과 일치**한다. UR-11/12의 "초급 → 15년차" 여정이 곧 깊이이며, 배지·그래프 노드·히트맵·진행 바·세션 리포트가 하나의 램프를 공유 → 학습자가 색을 한 번만 배우면 된다.
2. **다크 우선이지만 클리셰가 아니다**: 중립 근흑 + 형광 단일 액센트가 아니라, 청회 슬레이트 + 5단 깊이 램프 + 상태색 3종의 **기능적 다색**.
3. **밀도와 차분함의 양립**: 위계는 명도 4단계(`bg → surface-1/2/3`)와 텍스트 3단계(`fg / muted / subtle`)로 처리, 채도는 데이터에만 → Linear·Geist 수준의 조용함.
4. **장기 사용성**: 채도 낮은 배경(C≈0.02)은 순흑 대비 할레이션(halation)이 적고, D2의 읽기 타이포는 설정 옵션으로 흡수.
5. **구현 경제성**: Tailwind v4 `@theme` + shadcn 변수 매핑에 그대로 얹힘, 추가 폰트는 D2Coding 1종.

D1의 "빨간 연필 첨삭" 메타포는 **백지노트 피드백 화면**에서만 부분 차용(누락 KU = 회색 점선 밑줄, 오개념 = `--incorrect` 물결 밑줄).

## 7. 추천안 구현 사양 (UI 표준정의서 입력)

### 7.1 토큰 구조 (설계 사양 — 최종 코드는 개발 단계에서 작성)

```css
/* tokens.css — 단일 소스. Tailwind v4 CSS-first */
@custom-variant dark (&:where([data-theme="dark"], [data-theme="dark"] *));
:root            { --bg: oklch(0.985 0.004 230); --fg: oklch(0.23 0.03 250); /* …light… */ }
[data-theme=dark]{ --bg: oklch(0.20 0.02 245);   --fg: oklch(0.955 0.008 230); /* …dark… */ }
@theme inline {
  --color-bg: var(--bg); --color-fg: var(--fg);
  --color-depth-1: var(--depth-1); /* … depth-5, due, correct, incorrect, focus */
  --font-sans: "Pretendard Variable", system-ui, sans-serif;
  --font-mono: "JetBrains Mono Variable", "D2Coding", ui-monospace, monospace;
  --font-display: "Geist Variable", "Pretendard Variable", sans-serif;
}
/* 상태 파생: hover = color-mix(in oklch, var(--surface-2), var(--fg) 6%) */
```

- **기본 테마 = 시스템 추종 + 첫 실행 시 다크**. `data-theme` 속성으로 전환, `<head>` 인라인 스크립트로 FOUC 방지.
- 3변수 테마 생성기(Linear 원리): `base hue(245)`, `depth ramp(185→280)`, `contrast(표준/고대비)` → 고대비 모드는 `fg-muted`·`border-*`를 한 단계씩 상향(WCAG AAA 7:1 옵션).
- 금지: 컴포넌트에서 Tailwind 기본 팔레트(`bg-blue-500`)·임의값 색(`bg-[#…]`) 사용 — Biome/grep lint로 차단.

### 7.5 데이터 시각화 규칙

- 범주색 팔레트를 새로 만들지 않는다: **순서형 = 깊이 램프**, **이진 = correct/incorrect**, **강조 = due**. 섹션 구분은 색 대신 아이콘+레이블(10여 개 섹션에 10색 부여 금지).
- 히트맵(주간 리듬)은 "푼 문제 수"가 아니라 "그날 도달한 최대 깊이" 색 — 양보다 깊이를 보상(BL-07).
- 차트 숫자는 `tabular-nums`, 축 레이블 `text-2xs` `fg-subtle`, 그리드선 `border` 토큰.

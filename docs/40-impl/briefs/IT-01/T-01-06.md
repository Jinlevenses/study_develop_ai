### 4.1 포트 (`application/learner-model/ports.ts`에 **추가** export — 정본)

```ts
import type { LedgerEventEnvelope } from '@fathom/contracts/ledger/envelope';
import type { SqlitePort } from '@fathom/shared-kernel/sqlite/sqlite';
import type { CardRow, ConceptRow, ProjectorParams } from '../../domain/learner-model/projector/types.js';

/** 리플레이 리더 — 구현 = T-01-02 `infra/ledger/replay-source.ts`(createLedgerReplayReader). T-01-02 §4.1 LedgerReplayReader와 구조 동일.
 *  모든 메서드는 최신 schema_version으로 upcast + LEDGER_PAYLOADS 검증된 envelope를 낸다. db = 호출자 연결(읽기 전용 가능). */
export interface LedgerReplaySource {
  replay(db: SqlitePort): IterableIterator<LedgerEventEnvelope>;                      // ORDER BY client_ts, device_id, device_seq
  byCard(db: SqlitePort, cardId: string): IterableIterator<LedgerEventEnvelope>;      // 같은 총순서
  byConcept(db: SqlitePort, conceptId: string): IterableIterator<LedgerEventEnvelope>;
  corrections(db: SqlitePort): IterableIterator<LedgerEventEnvelope>;                 // evidence.voided · evidence.weight_adjusted
  maxRowid(db: SqlitePort): number;                                                   // 빈 원장 0
  sinceRowid(db: SqlitePort, after: number): IterableIterator<LedgerEventEnvelope>;   // rowid 순(캐치업 전용)
}

/** 원장 append와 같은 BEGIN IMMEDIATE tx 안에서 동기 호출. T-01-02 §4.1 ProjectionApplier와 구조 동일(ledger 코드 import 0).
 *  Promise 반환 금지. 예외(ts-fsrs FSRSValidationError 포함)는 감싸지 말고 그대로 던진다 — 경보·롤백은 writer 몫. */
export interface ProjectionApplier {
  apply(db: SqlitePort, event: LedgerEventEnvelope): void;
}

/** policy_version('ps_<16hex>') → 불변 파라미터 세트. 실패 = ProjectionParamsError throw. */
export interface ProjectorParamsResolver {
  resolve(db: SqlitePort, policyVersion: string): ProjectorParams;
  /** policy.switched를 볼 때마다 호출(라이브·리플레이 공통). 같은 ps 재등록 = no-op, 다른 members = invariant throw. */
  register(policyVersion: string, members: Readonly<Record<string, { readonly version: string; readonly sha256: string }>>): void;
}

/** 투영 저장소(테이블 = 라이브 또는 shadow). 구현 = infra/db/learner-model-store.ts(DB) · test 메모리 구현. */
export interface ProjectionStore {
  getCard(cardId: string): CardRow | null;
  putCard(row: CardRow): void;
  getConcept(conceptId: string): ConceptRow | null;
  putConcept(row: ConceptRow): void;
}

/** 정정 대상 event_id → 그 이벤트의 card_id·concept_id(lr_event STORED 열). 구현 = infra/db(SQL) · test 메모리. */
export interface EventTargetLookup {
  keysOf(db: SqlitePort, eventIds: readonly string[]): { readonly card_ids: readonly string[]; readonly concept_ids: readonly string[] };
}
```

### 4.3 리듀서 규칙 (`projector/apply.ts`·`fsrs/**`·`elo/**`·`mastery/**` — 순수, 시계·난수·I/O 0)

공개 함수(시그니처 고정): `apply(state: ProjectionSlice, event: LedgerEventEnvelope, params: ProjectorParams | null, corrections: CorrectionIndex): ProjectionSlice`(바뀐 키만 새 객체, 나머지 참조 유지) · `buildCorrectionIndex(events: Iterable<LedgerEventEnvelope>): CorrectionIndex` · `foldEvents(events: Iterable<LedgerEventEnvelope>, resolve: (ps: string) => ProjectorParams, corrections: CorrectionIndex): ProjectionSlice` · `buildProjectorParams(ps, fsrs, mastery): ProjectorParams` · `trackOfConcept(conceptId): string`(시드 `<track>.<slug>` → `<track>`, 사용자 `u.<ns>.<slug>` → `u.<ns>`) [Brief 결정 — payload에 track 없음].

| 이벤트 | 효과 (params = payload.policy_version으로 해석; `policy.switched`만 null) |
|---|---|
| `card.enrolled` | 카드 없으면 생성: `createEmptyCard(client_ts)` → 숫자화(`due`·`last_review` = `getTime()`/null), `last_fsrs_at: null`, `leech: false`, `status: 'active'`, tier·facet·response_mode = payload. 있으면 `last_ts`만 갱신. 개념 행이 없으면 초기 개념 행 생성(아래 초기값) |
| `card.status_changed` | `status` 교체, `last_ts` 갱신 |
| `attempt.graded` | ① 루트 = 자기 id. `voided` ∋ 루트 → **아무것도 안 함**(FSRS·Elo 모두 제외, SP-3 `foldCard` 동일) ② 유효 필드 = `latestSupersede.get(루트)`가 있으면 그 이벤트의 Verdict 필드(result·w_format·w_grader·gaming_factor·rapid·format·item_beta·item_n_options·response_mode), **`study_day`는 원 이벤트 값 유지** ③ `adjustments`를 총순서대로 적용: `factor` → `gaming_factor × factor`, `set` → null 아닌 성분만 교체 ④ **FSRS**: 원 이벤트의 `rating`(supersede 무관 — `rating_applied:false`)이 null이 아니고 `result ≠ 'pending'` ∧ 카드 `status = 'active'`면 `schedulers[tier].next(cardInput, now, rating)`, `now = max(fsrs_at, last_fsrs_at ?? fsrs_at)`, `last_fsrs_at = now`. 카드가 없으면 payload로 암묵 생성 후 적용 [Brief 결정] ⑤ **Elo·숙달**(아래 식) ⑥ 카드·개념 `last_ts = client_ts` |
| `evidence.upgraded`·`evidence.regraded` | 자기 위치에서는 `last_ts`만 갱신(효과는 인덱스로 원 이벤트 위치에 반영). FSRS 반영(`self_assessment.recorded{regrade_rating_confirm}`)은 IT-02 WP-02-01 [Brief 결정] |
| `evidence.voided`·`evidence.weight_adjusted` | 자기 위치 효과 0(인덱스로 반영) |
| `policy.switched` | 투영 효과 0(resolver 등록은 infra) |
| 그 밖 9종 | 효과 0(IT-01 범위 밖: lifecycle·track_level·mc_state·setting은 IT-02~03 WP) |

- **Elo**(ADR-011 §5, SP-6 F0·F4): `obs = {correct:1, partial:0.5, incorrect:0}`[Brief 결정] · `pending`(result 또는 `pending` 필드) → Elo·카운터 전부 건너뜀. `w = rapid ? 0 : w_format × w_grader × gaming_factor` (`mastery/evidence.ts` `evidenceWeight`) · `c = guess_correction && item_n_options > 0 ? 1/item_n_options : 0` · `P(θ) = c + (1−c)·σ(θ − item_beta)` · `n_graded += 1`(비보류·비무효 채점 이벤트, w = 0 포함) · `w > 0`이면 `K = α/(1 + b·n)`, `θ += w·K·(obs − P(θ))`, `n += 1`, `w_sum += w`, `beta_wsum += w·item_beta` · θ_q: `w > 0 ∧ geq(w_format, theta_q.w_format_min) ∧ geq(w_grader, theta_q.w_grader_min)`일 때만 `K_q = α/(1 + b·n_q)`, `θ_q += w·K_q·(obs − P(θ_q))`, `n_q += 1`. **clamp 없음**(정책에 키 없음). 초기 개념 행: `theta = theta_q = theta_prior`, 카운터 0, `credited_formats {}`, `study_days []`, `mastery {p: σ(θ̃ − 0), mastered:false, provisional:false}`, `first_mastered_ts null`.
- **실효·수축**(`elo/theta.ts`): `θ_eff = min(θ, θ_q + unqualified_ceiling)` · `θ̃ = θ_prior + (θ_eff − θ_prior)·n_graded/(n_graded + theta_shrink_n0)` · `thetaVisible(n_graded) = n_graded ≥ theta_display_min_events`(UI용 export).
- **숙달**(`mastery/mastery.ts`): `β̄ = w_sum > 0 ? beta_wsum / w_sum : 0`(SP-3 규칙) · `p = σ(θ̃ − β̄)` · 형식 산입 = `result = 'correct' ∧ !pending ∧ !rapid ∧ gaming_factor > 0 ∧ geq(w_format, mastery.format_counts.w_format_min) ∧ geq(w_grader, …w_grader_min)` → `credited_formats[format] ??= 루트 event_id`, `study_days ∪= 원 study_day` · `mastered = geq(p, p_min) ∧ |credited_formats| ≥ formats_min ∧ |study_days| ≥ distinct_days_min` · 처음 참이 된 `client_ts` → `first_mastered_ts`(이후 거짓이 돼도 유지). `geq(a, b) = a ≥ b − epsilon`.
- **β 갱신**(`elo/item-beta.ts`, CR-29·UT-LR-115): `itemBetaAfter(conceptBefore: ConceptState, fields, params): number | null` = `w ≤ 0 ∨ pending → null`, 그 밖 `item_beta + K·w·(P(θ) − obs)`(K·P는 갱신 **전** 개념 상태 기준) [Brief 결정 — 문항 노출 수를 투영이 모르므로 학습자 K 재사용]. 리듀서 상태에는 저장하지 않는다(T-01-09가 outbox payload에 실음).
- **grade·gaming 헬퍼**(T-01-09가 payload 생성에 사용, UT-LR-102·111): `fsrs/grade.ts` `fsrsRating({result, pending, recommended_grade, response_mode, rapid, hints_used}, gaming: GamingParamsV1): FsrsRating | null` = pending → null · r = recommended_grade · recognition → min(r, 3) · rapid → min(r, `rapid.grade_cap`) · `hints_used ≥ 2` → min(r, 2), `= 1` → min(r, 3). `mastery/evidence.ts` `tMinMs(format, promptChars, gaming) = max(floor_ms, base_ms + promptChars/chars_per_s·1000)` · `isRapid(latencyMs, tMin) = latencyMs < tMin` · `evidenceWeight(...)`.
- 모든 숫자 결과가 유한하지 않으면 `throw new Error('invariant: projector produced non-finite …')`(정준 JSON 보호).

### 4.4 증분 적용 (`application/learner-model/incremental.ts` + `infra/projection/applier.ts`)

`applyIncremental(deps: { db; source: LedgerReplaySource; targets: EventTargetLookup; store: ProjectionStore; params: ProjectorParamsResolver }, event)`:
1. `policy.switched` → `params.register(...)` 후 반환. 투영 효과 없는 타입(§4.3 표 "그 밖") → 반환.
2. 영향 키: `card.*`·`attempt.graded`·`evidence.upgraded/regraded` = payload의 `card_id`·`concept_id` · `evidence.voided/weight_adjusted` = `targets.keysOf(db, target_event_ids)`.
3. **fast path** = 타입 ∈ {`card.enrolled`, `card.status_changed`, `attempt.graded`} ∧ 대상 카드가 없거나 `card.last_ts < client_ts` ∧ (`attempt.graded`면) `last_fsrs_at === null ∨ last_fsrs_at < fsrs_at` ∧ 개념이 없거나 `concept.last_ts < client_ts`(전부 **엄격**) → store에서 해당 행만 읽어 `apply(slice, event, params, EMPTY_CORRECTIONS)` → 바뀐 행 put.
4. 그 밖(정정·지각 도착·동률) = **키 재도출**: `idx = buildCorrectionIndex(concat(source.corrections(db), 개념 키마다 source.byConcept(db, c) 중 upgraded/regraded))` → 카드 키마다 `foldEvents(source.byCard(db, id), resolve, idx)`의 그 카드 행, 개념 키마다 `foldEvents(source.byConcept(db, id), …)`의 그 개념 행을 put(fold 결과에 행이 없으면 put 생략 — 원장에서 사라지는 키는 없다).
5. `createProjectionApplier(deps)`의 `apply(db, e)` = `applyIncremental({db, store: createProjectionStore(db, LIVE_TABLES), …}, e)` → 끝에 `ensureProjectionMeta(db, clock)`(§4.6). **동기 함수, tx를 열지 않는다**(writer tx 안).
